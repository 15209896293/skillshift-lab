## 1. 背景与产品目标

SkillShift Studio 面向允许 AI 协作的职业任务，连接教师任务设计、学生完成任务、过程说明与教师复核。Studio 的价值是让任务和人机协作过程更清楚、可复核、可干预；不是阻止学生在平台之外使用 AI，也不是与通用 Agent 比拼模型能力。

本候选需求聚焦四个体验目标：

1. 教师可以与作业设计 Agent 对话，并把确认后的结构化任务发布给学生。
2. 不同任务的要求可以按明确的任务结构展示，不被固定成一张不适合所有任务的表单。
3. 学生进入任务后清楚知道目标、步骤、提交物和当前进度，同时有足够空间处理项目材料。
4. 模型配置和任务内辅助能力易于使用，同时不把 API Key 暴露给学生浏览器或客户端。

## 3. 用户与场景

### 教师 / 任务设计者

教师上传或选择教学资料，说明希望学生完成的任务。作业设计 Agent 提取材料内容、整理成结构化任务草稿，并标注生成内容对应的来源位置；教师审核、修改和预览后决定是否发布。

### 学生

学生打开已发布任务，先了解目标、步骤、交付物和提交要求；随后在任务工作区查看材料、编辑项目、使用任务允许的工具，并提交成果与必要的验证说明。学生工作区顶部显示本任务的平台 AI 可用状态；右侧工具区可切换文件、内置浏览器和 Agent。

### 产品运营者 / 学校管理员（后续角色）

为组织配置获准的模型服务、凭据引用、预算和可用范围。当前合成原型没有真实身份和生产控制面，不能假设此角色及其权限已经具备。

## 4. 功能需求

### 4.1 教师与作业设计 Agent

#### 资料生成任务草稿

教师的最小发布单元是**一项有明确目标、学生责任、交付物和检查要求的任务**。教师可以把 DOCX、PPTX、PDF、Markdown 等课程材料交给作业设计 Agent，让 Agent 先整理重点、提出任务草稿和检查缺口。

| ID | 优先级 | 需求 |
| --- | --- | --- |
| SRC-01 | P0 | 教师可上传一个或多个经允许的任务资料文件，并看到文件名、解析状态、失败原因和移除入口。首期白名单为 DOCX、PPTX、PDF、MD、TXT；建议每个文件不超过 20 MB、每项任务最多 5 个文件；暂不接收 XLSX 和压缩包。 |
| SRC-02 | P0 | 系统提取资料后，任务草稿中的关键要求须可回溯到来源文件和页/幻灯片/标题段落位置；无法从资料确认的内容标为“待教师补充”，不由 Agent 编造。 |
| SRC-03 | P0 | Agent 生成结构化任务草稿，至少包括任务目标、学生对象/角色、材料、操作步骤、交付物、验证/检查点、学生责任、平台 AI 协作模式和教师补正方式；教师审核并显式确认后才可发布。 |
| SRC-04 | P0 | 上传资料中的文字只作为待分析内容，不作为执行指令；系统不得执行文档中的宏、链接、嵌入程序或要求访问本机/外部系统的内容。 |
| SRC-05 | P0 | 在使用真实外部模型前，界面须明确资料会发送给哪个服务商、用途和数据边界，并通过模型 Gate；演示阶段只使用合成或获准的非敏感资料。 |
| SRC-06 | P1 | 教师可查看原文片段与生成字段的对应关系，逐项接受、修改或退回 Agent 重整；原始资料保持只读，不被改写。 |

“各类文档”需要转成可维护的格式白名单，而不是无限接受任意二进制文件。若某份资料结构复杂或解析失败，系统应提示教师手工补充，不应静默生成看似完整但没有来源依据的任务。

| ID | 优先级 | 需求 |
| --- | --- | --- |
| TCH-01 | P0 | 教师可通过对话描述教学目标、任务背景、材料、交付物、学生必须承担的验证/解释责任和期望的 AI 协作方式。 |
| TCH-02 | P0 | Agent 将对话整理为结构化任务草稿，并同步更新右侧任务预览；Agent 生成的内容必须明确为草稿，发布前由教师确认。 |
| TCH-03 | P0 | 教师可直接编辑结构化字段、要求 Agent 修改指定部分、撤销/重做尚未发布的建议，并能识别哪些字段仍缺失或相互矛盾。 |
| TCH-04 | P0 | 发布前提供学生视角预览，至少展示任务目标、材料、提交要求、学生责任、平台内 AI 模式、记录范围和补正路径。 |
| TCH-05 | P0 | 任务采用“共同核心字段 + 已审核任务类型模块”：共同字段定义目标、背景、材料、交付、验证/检查点、人类责任、协作模式和告知；特定任务模块只显示该类任务需要的字段。 |
| TCH-06 | P1 | 保存未发布草稿并在返回设计器后恢复；发布后固定版本快照，后续编辑产生新修订，不静默改变已发布任务。 |
| TCH-07 | P1 | 设计器显示模型状态、超时/错误和降级状态；模型不可用时保留教师手工编辑任务的路径，不伪造 Agent 已生成内容。 |

### 4.2 任务结构与动态展示

任务预览不应依赖 AI 临时生成任意格式，也不应要求所有任务填写同一组代码字段。建议用稳定的任务契约承载共同内容，并通过审核过的类型模块描述不同任务的输入、过程、交付和验证要求。

每个任务至少应有以下共同字段：

- 任务标题、目标与背景；
- 材料/项目上下文及其来源；
- 最终交付物；
- 可操作的完成步骤或里程碑；
- 任务相关的验证方法或人工检查项；
- 学生必须亲自完成的判断、验证、解释、纠错或接管责任；
- 平台内 AI 协作模式、可观察范围、教师可见内容和提交/补正路径。

任务类型模块可以定义字段、显示条件和验证方法，但不得绕过共同隐私、安全、学生责任和证据边界。首个模块应等首个任务族确认后再定，不能借此同时扩展 Python、SQL、Hadoop 等多个任务域。

### 4.3 模型服务与凭据配置

| ID | 优先级 | 需求 |
| --- | --- | --- |
| MOD-01 | P0 | 模型层采用通用 Provider/Model Adapter 契约；前端通过供应商预设档案选择服务商与模型，API 协议、默认地址和必要参数由适配器预先配置，不要求用户手填接口细节。DeepSeek 是首个演示档案，不是唯一支持路线。 |
| MOD-02 | P0 | 教师/本机演示负责人可通过简洁流程选择服务商、模型并配置 API Key；学生不出现模型账号或 Key 配置入口。首期界面采用本机单用户配置，不建设生产用户数据库或租户体系。 |
| MOD-03 | P0 / Gate B | 合成演示可保存服务商/模型选择并模拟“已配置”状态，但不得要求输入或持久化真实 Key。真实 Key 接入前须有获准的服务端安全凭据存储；不得放入 `localStorage`、浏览器明文配置、URL、源码、普通日志或提交包。 |
| MOD-04 | P1 / Gate B | DeepSeek 演示档案接入前需明确真实请求的数据内容、费用上限、模型版本、超额/不可用处理和显式连接测试行为。没有 Gate B 授权前，模型配置界面可以使用合成状态演示，但不得发起真实外部请求或产生费用。 |
| MOD-05 | P1 / Gate B | 连接失败、额度耗尽和服务不可用时显示明确状态；不静默切换供应商。模型凭据状态仅显示已配置/未配置/验证失败等信息，不提供读取已保存 Key 的能力。 |
| MOD-06 | P2 | 供应商适配器沿白名单扩展；自定义 endpoint、任意协议参数和学生自带 Key 不在本需求范围，若要支持须单独评审数据与安全边界。 |

本稿把“上线前不做用户数据库”理解为：**本机/合成演示不建设生产身份、租户与应用用户数据库**。这不代表可以把真实 API Key 明文保存在浏览器；安全凭据存储是模型账号配置的独立依赖。真实调用还需要费用、数据路径与供应商 Gate。

### 4.4 平台内 AI 协作模式

| ID | 优先级 | 需求 |
| --- | --- | --- |
| AI-01 | P0 | 发布任务时教师从固定三种平台内协作模式中选择一种；学生开始任务前看到模式名称、可用能力和记录范围。 |
| AI-02 | P0 | **平台 AI 对话**：学生可在任务上下文中向 Agent 提问并接收解释/引导；不允许 Agent 自行修改文件、执行命令或控制浏览器。 |
| AI-03 | P0 | **Agent 任务内协作**：Agent 可在任务授权的工作区读取任务文件、提出计划并生成修改建议；涉及写入的建议展示差异并由学生确认。默认不含 Shell、代码执行、安装依赖和浏览器自动化。 |
| AI-04 | P0 | **无平台内 AI/Agent**：学生不显示或不能调用平台提供的 AI/Agent；学生独立完成同一任务并提交要求的结果与说明。 |
| AI-05 | P0 | 界面说明“无平台内 AI/Agent”只控制本平台能力，无法识别或阻止学生使用平台外 AI、浏览器、手机或其他设备；不得称为“禁止/检测所有 AI”。 |
| AI-06 | P1 | 三种模式映射至平台预先审核的能力档案；教师和作业设计 Agent 不得放宽系统级隐私、工具、网络或执行限制。 |

建议首期固定上述三种模式。Agent 模式提供的是受限的任务内文件协作体验，不等于开放任意 Agent 权限；后续若需运行代码或 Agent 操作浏览器，应另过安全 Gate。

### 4.5 学生任务体验与工作区

| ID | 优先级 | 需求 |
| --- | --- | --- |
| STD-01 | P0 | 学生打开任务后，首屏清楚显示任务标题、目标、交付物、平台 AI 模式和当前下一步；本项目本阶段不引入任务截止时间。 |
| STD-02 | P0 | 任务说明/步骤作为可折叠任务面板，放在工作区顶部提交/状态操作栏附近；默认显示简短目标与进度摘要，学生可随时展开全部要求。折叠不得隐藏安全限制、学生责任或提交要求。 |
| STD-03 | P0 | 学生可查看任务阶段/检查点、当前状态、已完成项及待完成项；状态和检查项来自任务定义，不以装饰性进度条暗示学习能力或成绩。 |
| STD-04 | P0 | 中央工作区采用 IDE 式项目交互：有文件/材料树或清晰入口、多文件标签、语言感知编辑、行号/格式支持和未保存状态；不能只呈现为与任务无关的普通网页输入框。 |
| STD-05 | P0 | 右侧提供可折叠/可调宽的上下文工具区，可在文件查看、内置浏览器和 Agent 面板间切换；窄屏下可收纳为抽屉，主编辑区保持可用。 |
| STD-06 | P0 | 学生工作区顶部显示可见的“本任务 AI 状态灯”及文本状态：绿色表示该任务允许的平台 AI 当前可用；灰色表示该任务不提供平台 AI；黄色表示允许但暂不可用或正降级。颜色旁必须有文字/可访问标签；绿色不代表回答正确、任务安全或隐私已获保证。 |
| STD-07 | P0 | 在代码执行安全 Gate 关闭期间，不提供可运行学生代码的按钮；如显示运行位置，必须明确“运行暂未开放”，不能伪造运行成功或验证结果。 |
| STD-08 | P1 | 未提交编辑草稿能够按任务隔离地保存/恢复；刷新、切换任务或网络失败后，清楚显示最后保存状态，并避免用另一个任务的数据覆盖当前草稿。首期本机演示可先使用有范围说明的本地/进程内状态，不强制生产数据库。 |
| STD-09 | P1 | 学生提交前看到提交清单，包括交付物、验证说明、未完成项和已知不确定处；提交后能查看教师反馈并按请求说明、补证、补正或重交。 |

右侧“内置浏览器”是给学生自行查看任务相关或自行选择的网页资料；浏览器打开本身不等于允许 Agent 自动浏览、读取 Cookie、下载文件或填写网页表单。浏览器能力仍需明确隔离和允许的导航/数据范围。这里的“IDE 感”不代表当前阶段需要开放终端、依赖安装、Shell、任意文件访问或代码执行。

### 4.6 任务材料与内置浏览器

| ID | 优先级 | 需求 |
| --- | --- | --- |
| WEB-01 | P0 | 学生工作区右侧工具区可显示文件列表/预览、内置浏览器和 Agent 三类面板；面板可切换、收起，不能覆盖或丢失中央编辑器内容。 |
| WEB-02 | P0 | 学生可在内置浏览器中自行打开任务链接或自行选择网页资料；打开的内容须处于学生可见的当前任务工作区。 |
| WEB-03 | P1 | 内置浏览器首期支持学生手动打开任务链接及公开网页；暂不支持网页登录、文件下载和 Agent 代操作。不向教师或研究层记录完整浏览历史、Cookie 或页面输入内容；仅收集任务流程确需的最小事件。 |
| WEB-04 | P2 / 独立 Gate | 学生自行浏览与 Agent 网页搜索/自动化分开授权；本需求不默认允许 Agent 读取网页、点击网页或提交表单。 |

右侧内置浏览器按“学生自行使用”理解；是否允许 Agent 操作浏览器是单独能力，默认关闭。登录、下载和任意网址访问需要另做安全范围评审。

### 4.7 大段粘贴事件与教师复核

| ID | 优先级 | 需求 |
| --- | --- | --- |
| PASTE-01 | P1 | 平台可记录受管编辑器内发生的粘贴事件及最小元数据，例如时间、目标文件、粘贴字符/行数区间；不记录剪贴板内容本身。 |
| PASTE-02 | P1 | 首期建议以单次粘贴达到 10,000 字符或 200 行作为“大段粘贴事件”提示阈值；教师界面呈现事实、阈值和限制，不给风险分或自动结论。阈值仅对受管编辑器可捕获事件生效。 |
| PASTE-03 | P1 | 学生可查看与该事件关联的记录说明，并按教师要求解释或补充任务证据；粘贴事件本身不阻止编辑、提交或自动扣分。 |
| PASTE-04 | P0 | 所有界面、报告和研究分析不得由粘贴量推断复制来源、外部 AI 使用、作弊、努力程度或能力。平台只知道受管编辑器内发生的粘贴，无法识别平台外的复制粘贴行为。 |

首期统一使用上述阈值，不按文件类型区分。事件仅对该任务学生和任课教师可见，随任务提交记录保留；不进入研究数据导出。学生在编辑器首次捕获粘贴事件前看到告知。阈值不能被描述为作弊判定标准。

### 4.8 输入代码检查与即时提示

用户提出希望“大量粘贴或不符合任务的代码能被发现”。这里拆成两类可观察事实，不能合并成作弊检测：

| ID | 优先级 | 需求 |
| --- | --- | --- |
| CODE-01 | P1 | 当学生在受管代码编辑区粘贴时，系统可按明确阈值显示“大段粘贴事件”，记录最小事件元数据；只能覆盖本编辑区实际捕获到的粘贴操作。 |
| CODE-02 | P1 | 对首期 Python + CSV 任务，可解析 Python 语法树（不执行代码），并检查任务约定的输出字段、必需 Artifact 和 CSV 列结构；提示应指出文件、位置、触发规则、可修正方向和检查范围。 |
| CODE-03 | P1 | 任务规则检查由版本化、可解释的确定性检查项提供；首期只覆盖语法可解析、CSV 必需列/输出文件存在等已声明规则，不判断代码风格、意图、来源或泛化“合规性”，不使用单一 LLM 判定。 |
| CODE-04 | P0 | 静态检查不得运行代码，不得把语法错误、格式问题或任务规则不匹配解释为作弊、外部 AI 使用、努力不足或能力不足；检查失败不自动阻断提交，除非任务契约明示该项是提交必需条件并提供修复/说明路径。 |
| CODE-05 | P1 | 当任务没有可验证规则时，界面必须显示“未配置任务检查”，不得假装已识别所有不符合要求的代码。 |

大段粘贴事件只能说明“在此编辑区发生了超过阈值的粘贴”；代码检查只能说明“某个明确规则的检查结果”。二者都不能确定代码来源或学生是否理解。

## 5. 端到端验收场景

### 主场景：教师用资料生成并发布一个有平台内 Agent 的项目任务

1. 教师上传 DOCX、PPTX、PDF、MD 或 TXT 资料，系统展示解析状态与来源位置；无法确认的内容标为待补充。
2. 作业设计 Agent 形成一项结构化任务草稿，教师在动态任务预览中核对、修改并明确确认；系统不自动发布。
3. 教师选择“Agent 任务内协作”，检查学生视角预览后发布。
4. 学生收到同一任务版本，顶部看到目标、提交物、当前步骤和 AI 状态灯；任务要求可折叠，右侧可切换文件、内置浏览器和 Agent。
5. 学生在编辑区完成 Python + CSV 任务，查看确定性静态检查提示；Agent 写入建议先展示差异并由学生确认，代码不会被执行。
6. 学生按任务要求提交 Artifact 与验证/解释说明。
7. 教师查看任务相关材料与可观察事实，选择认可或给出有理由的说明/补证/补正请求。
8. 学生看到对应请求，补充后重新提交；教师关闭该轮处理。

### 替代场景：无平台内 AI 的任务

教师可分别发布“平台 AI 对话”“Agent 任务内协作”或“无平台内 AI/Agent”任务。无平台内 AI/Agent 时，学生页面不显示平台 AI 操作入口，但仍显示任务目标、材料、提交、教师反馈和补正路径。产品明确说明无法观察或阻止学生使用外部工具。三种模式下任务结构和提交流程保持一致。

### 配置演示场景

在本机合成演示中，教师/负责人选择 DeepSeek 预设并看到账号配置界面及模拟状态；无需生产用户数据库，不发送真实请求、不产生费用，也不录入真实 Key。真实 Key 安全保存和真实服务调用另过 Gate。

### 验收原则

- 教师发布的任务字段、协作模式和版本能在学生端正确读回。
- 任务要求差异通过已审核的结构化任务类型模块呈现，不依赖自由格式文本猜测。
- 草稿/发布/提交/补正状态在页面和 API 中一致；失败或未确认状态不得显示为成功。
- 学生任务切换、刷新、提交失败和重试不丢失或串用其他任务草稿。
- 粘贴事件只产生有限、可解释的事实记录，不触发自动判分或作弊/能力结论。
- 模型 Key 从输入到存储、调用、错误和移除全程均不会返回学生客户端或进入日志/提交包。
- 当前只能以合成身份、合成任务和本机服务验收；真实模型、数据、课堂和生产结论分别通过独立 Gate。

## 6. 暂不纳入本候选需求的事项

- 真实模型调用、任意自定义 endpoint、学生自行配置 API Key、模型自动路由或静默供应商回退；
- 运行学生代码、Shell、依赖安装、浏览器自动化或 Agent 任意文件操作；
- 通过粘贴/行为数据自动判定作弊、能力、努力、成绩或 AI 使用来源；
- 全桌面监控、浏览历史监控、键盘记录和平台外活动采集；
- 真实身份、课程/班级导入、真实学生数据、研究数据导出、生产持久化或部署；
- 在首个任务族冻结之前支持多个职业任务域和任意教师自定义字段/验证器。

## 7. 首期默认决策与依赖

1. 完成 B0 资产/证据基线，并确定 `apps/studio-web/` 是否为唯一主演示面。
2. 首期产品切片采用 Python + CSV 数据质量/一致性任务；正式研究任务仍需定义材料、参考解、负例、确定性验证方式和至少两套迁移变体后再冻结。
3. 作业设计 Agent 首期由确定性合成适配器演示；不发起外部模型调用。
4. 首批资料白名单为 DOCX、PPTX、PDF、MD、TXT；建议每个文件 20 MB 内、每项任务最多 5 个文件；首期代码检查只做 Python 语法解析和任务明确声明的 CSV/产物规则。
5. 模型配置人为教师/本机演示负责人；首期保存供应商/模型选择和模拟状态，不录入真实 Key。未来真实 Key 必须进入服务端安全凭据存储；无需先建生产用户数据库。
6. Agent 只在任务工作区读取材料、整理草稿和提出文件差异；写入须由学生确认，不执行代码、不自动操作浏览器。内置浏览器供学生手动访问公开网页，不登录、不下载。
7. 大段粘贴提示阈值为单次 10,000 字符或 200 行；只记录编辑器内最小事件，不保留剪贴板内容，不推断来源或能力。
8. 完成 B0 资产/证据基线并确定 `apps/studio-web/` 是否为唯一主演示面，再把本需求拆成单一可实施规格；本稿整体不直接授权功能开发。

## 8. 后续验证事项

以下事项不阻塞首期合成演示，但在扩大范围前需要依据项目证据复核：

1. 通过真实教师试用确认资料格式、单文件 20 MB、每任务 5 个文件的限制是否足够；首期 XLSX 暂不支持。
2. 用 Python + CSV 任务样例验证静态检查只报告明确规则，且不会被误读为代码来源、作弊或能力判断。
3. 在实现设计阶段核实内置浏览器的站点隔离与安全边界；若不能安全承载公开网页访问，则首期退回到受限任务链接预览。
4. 在真实模型 Gate 前单独确定安全凭据存储、请求数据、费用上限和 Key 生命周期；不以没有生产用户数据库为由绕过这些要求。
5. 通过学生/教师可用性走查验证任务折叠区、AI 状态文案和粘贴事件告知是否易懂。

## 9. 产品建议与优先级

建议推进次序：

1. 先完成当前 React Studio 的浏览器验收，建立当前源码的可复现基线。
2. 用确定性合成能力实现“上传教学资料—生成带来源的结构化任务草稿—教师修改确认—动态预览”，先覆盖候选格式中的最小集合。
3. 在 Python + CSV 首期产品切片上实现同一任务的三种平台内协作模式，并明确任务规则和静态检查范围。
4. 调整学生端可折叠任务面板、顶部 AI 状态灯、IDE 式编辑区和右侧文件/内置浏览器/Agent 工具区；保持不执行代码，先完成端到端演示验收。
5. 记录受管编辑器的大段粘贴最小事件，并配置可解释阈值；不做来源识别、作弊判定或自动扣分。
6. 在本机合成演示中提供通用供应商配置交互，以 DeepSeek 作为演示档案；不建设生产用户数据库、不发起真实请求。真实 Key 持久化与模型调用另过 Gate。

理由：资料到任务草稿、任务发布、学生完成和教师复核构成可演示的核心闭环；配置交互可以先以合成状态验证易用性。真实模型调用和真实 Key 存储仍会引入费用与数据安全依赖，单独通过 Gate 后再接入。
