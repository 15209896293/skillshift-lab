# R0-SYNTHETIC-BUDGET-LIFECYCLE：合成预算生命周期契约

## 状态

- Task ID：`R0-SYNTHETIC-BUDGET-LIFECYCLE-001`
- 类型：FEATURE / Gate B 控制面本机安全契约
- 状态：**Implemented / Verified（2026-09-24；仅限本机 SQLite 与合成金额）**。
- 上游：ADR-009、ADR-012、ADR-013，及 `R0-SYNTHETIC-CONTROL-PLANE-PERSISTENCE-001`。

## 目标

在不进行真实模型调用、真实扣费或部署的前提下，验证未来持久预算账本的最小保守规则：

1. 请求发出前必须预留额度；
2. 尚未发出请求才可释放预留；
3. 一旦尝试向供应商发出请求，即使结果未知也必须保留额度并进入待对账状态；
4. 仅在记录一个不超过预留额的合成结算金额后，才可减少已占用额度；
5. 多进程与数据库重开后，累计占用额度仍不得超过 10,000 分（100 元）。

这是一份本机验证的状态机契约，不是费用、账单、供应商价格或生产数据库的实现。

## 允许范围

- Python 标准库 `sqlite3`，显式临时数据库路径，固定合成范围与固定 10,000 分月度上限；
- 预留、未派发释放、派发后待对账、合成结算、幂等与冲突拒绝；
- 有限时的本机多进程/重开测试、规格、测试和 Artifact。

## 禁止范围

- 真实 DeepSeek 或其他供应商调用、真实 Key、实际价格、账单、扣费、退款或退款承诺；
- 真实学生、真实身份、学校账户、数据导出、ECS、云数据库、迁移、部署；
- 自动将“派发结果未知”释放为零成本，或把本机 SQLite 描述为生产账本。

## 状态机（Proposed，仅对本任务合成数据）

```text
RESERVED --未派发失败--> RELEASED_BEFORE_DISPATCH
RESERVED --尝试派发--> RECONCILIATION_REQUIRED --合成结算--> SETTLED
```

`RESERVED` 与 `RECONCILIATION_REQUIRED` 按预留金额占用预算；`SETTLED` 按合成结算金额占用预算；只有 `RELEASED_BEFORE_DISPATCH` 不占用预算。所有未知派发结果默认保守地占用预留金额。
