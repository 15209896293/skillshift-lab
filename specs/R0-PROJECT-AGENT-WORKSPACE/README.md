# R0 项目型 Agent 工作空间

## 状态

- Task ID：`R0-PROJECT-AGENT-WORKSPACE-001`
- 类型：PRODUCT / FEATURE DEFINITION
- 状态：**Active product scope; implementation split into gated features**。
- 上游：`docs/product/R0_PROJECT_AGENT_WORKSPACE_DECISION.md`、`docs/product/R0_PRODUCT_REPOSITIONING_DECISION.md`、`docs/product/R0_RESEARCH_TASK_EVIDENCE_CONTRACT.md`、ADR-006 至 ADR-013。
- 保留：`R0-AGENT-FIRST-VERTICAL-SLICE-001` 是合成流程 Harness 的已验证范围，不是本产品工作空间的实现证明。

## 1. 目标

定义第一个真实产品方向上的项目协作体验：教师创建一个职业项目任务；学生在独立工作空间中围绕任务材料/代码使用 Agent；学生检查结果并提交说明；教师根据清楚、有限、任务相关的信息反馈，学生可以补正。

首个场景使用合成 Python + CSV 数据质量/一致性任务。它只是职业教育切片假设，不得描述成学校本地历史作业、真实任务需求或研究结果。

## 2. 用户目标与待验证假设

| 角色 | 目标 | 假设状态 |
| --- | --- | --- |
| 教师/导师 | 不需设计复杂系统策略即可布置 AI 协作项目，并能快速理解提交、验证和需反馈之处 | 未经真实教师验证 |
| 学生 | 在同一任务工作空间理解任务、使用 Agent 和项目材料、审查修改/结果、承担必要验证并提交 | 未经真实学生验证 |
| 平台运营者 | 控制身份、任务可见范围、模型、预算、审计和数据生命周期 | 生产控制面未就绪，ADR-013 仍 0/28 |

不能以页面原型、自动化测试或 Agent 输出替代用户价值证据。

## 3. 用户旅程与功能契约

### 3.1 教师 Web

1. 从一个可复用的合成职业项目模板开始；
2. 明确目标、学生交付、学生亲自验证/解释的责任；
3. 选择简明的 AI 协作模式；初始展示采用“协作需确认”，不要求教师配置复杂工具权限；
4. 预览学生任务工作区与提交要求，再模拟发布；
5. 在独立复核入口查看提交物、明确的验证/说明和必要事件引用；
6. 选择认可、请求说明、请求补证、请求补正或环境问题，并提供简短理由。

### 3.2 学生项目工作空间

1. 接收任务并看到允许的 Agent 协作方式、任务内记录和教师可见范围；
2. 在任务上下文中查看项目材料和代码；
3. 向 Agent 提问、查看计划和建议；对于拟议修改，能查看差异并确认、拒绝或接管；
4. 在代码执行 Gate 关闭前，运行控件必须禁用或显式标明“未开放”，不能伪造真实运行结果；
5. 提交与任务相关的代码/Artifact、验证说明、依据和不确定之处；
6. 收到教师请求后，能补充说明、补证、改动或重新提交。

### 3.3 平台服务

至少需要版本化的 Assignment/Task、Workspace Session、Agent Turn/Proposed Action、Artifact Reference、Evidence Event、Submission、Review Action 和 Remediation；最小权限原则适用。生产身份、持久化、真实模型和数据保留尚未实现/开放。

控制面服务可以负责任务、模型网关和元数据，但不执行学生代码。执行面需通过独立安全 Gate，运行位置和 Provider 未选定。

## 4. 首期范围

### 包含

- 独立教师 Web 和学生工作空间信息架构；
- 首个合成职业任务；
- Agent 对话/计划/修改建议与学生决策点的体验规格；
- 学生代码编辑和项目材料展示的目标体验；
- 任务提交、教师复核、反馈和补正工作流；
- 前后端共享数据/API/事件边界；
- 先以本地合成数据完成 UI 原型，再逐步形成一条集成纵向切片。

### 不包含，除非对应 Gate 另行通过

- 真实学生/教师身份、班级导入、真实课程材料或研究数据；
- 真实 DeepSeek API 调用、真实 Key 或任何用户端 Key 配置；
- 本机或云端学生代码执行、依赖安装、Shell、浏览器自动化或 Agent 任意文件操作；
- ECS 连接/部署/端口/真实数据库；
- 分数、作弊/外部 AI 检测、能力/努力推断、全量日志监控；
- 自动扩展成完整 LMS、多学校租户或多任务目录。

## 5. 设计与实施顺序

| 阶段 | 产出 | Gate / 限制 |
| --- | --- | --- |
| P0. 产品契约 | 用户假设、代表任务、教师/学生工作、责任与验证边界 | 合成任务可内部审查；真实需求仍 UNKNOWN |
| P1. 教师端 | 单独的教师 Web 任务创建、预览、复核/补正原型 | 使用合成身份/数据；先验结构与交互 |
| P2. 学生端 | 独立学生项目工作台设计和原型：材料/代码、Agent、建议差异、提交 | 代码运行关闭；确定性或显式模拟 Agent |
| P3. 控制面契约 | API、领域数据、角色权限、事件/提交版本、失败和同步行为 | 先本机契约测试，不代表生产后端 |
| P4. 集成纵向切片 | 教师发布 → 学生 Agent 协作/提交 → 教师反馈 → 学生补正 | 使用合成数据；模型和执行能力仍独立 Gate |
| P5. 模型 Gate | DeepSeek 服务端网关、真实费用/预算/数据流验证 | 遵守 ADR-006 至 ADR-013；生产就绪为 0/28 时不得调用/部署 |
| P6. 执行 Gate | 候选本机或独立远端隔离执行环境的攻防和恢复证据 | 未通过前禁止运行外来或学生项目；现有 ECS 不执行代码 |
| P7. 用户验证 | 获批的自愿、非计分教师/学生走查 | 不可从合成结果推断课堂/学习/研究结论 |

用户体验顺序为教师端 → 学生端 → 后台界面；工程依赖上，共享 API/事件/权限契约必须在实现两端集成前定义，后台控制面不能被完全推迟到前端完成后才设计。

## 6. 产品验收方向

1. 教师可从合成模板明确任务目标、学生责任、协作方式、交付和验证要求；系统不要求其配置监控/评分规则。
2. 学生页面与教师任务定义一致且为独立入口；包含项目上下文和面向代码任务的工作区，不是只有聊天标签。
3. Agent 建议与已执行事实明确区分；所有修改建议有可检查的差异，人类可确认/拒绝/接管。
4. 代码执行未通过 Gate 前没有实际运行路径，也不产生假运行证据。
5. 学生提交包含项目产物与任务要求的验证/解释，不将 Agent 对话单独当提交。
6. 教师复核引用具体提交/事件，动作有理由，学生能解释、补证或补正。
7. 运营事件与研究数据分离；界面不推断作弊、外部 AI 来源、能力或学习成效。
8. 两端与 API 合同在本机合成环境可进行端到端回放；真实模型、生产身份、部署均单独标注未实现。

详细 UI 规格由后续单项任务补齐。教师端首项在 `specs/R0-TEACHER-WORKSPACE/README.md`，不可把本规格本身视为界面实现或真实用户验证。

## 7. 停止条件

遇到真实用户招募/联系、真实数据、模型调用/凭据、代码执行、执行 Provider 选择、ECS/部署/开端口、数据保留、付费或身份/授权决策时，停止对应扩展并提交明确决策项；不因项目长期运行授权而越过既定 Gate。
