# R0-DEEPSEEK-BUDGET-RECONCILIATION-RESEARCH：费用对账方案研究

## 状态

- Task ID：`R0-DEEPSEEK-BUDGET-RECONCILIATION-RESEARCH-001`
- 类型：RESEARCH / DOC
- 状态：**Proposed research（2026-09-24；仅基于代码与公开官方文档）**。
- 上游：ADR-007、ADR-008、ADR-009、ADR-013、PCP-17。

## 目标

为未来 DeepSeek 合成探针定义可审计的费用估算、预算预留、供应商账单核对和告警方案，找出在真实调用前仍必须补齐的技术边界。

## 允许范围

- 只读审阅现有 DeepSeek 契约、运行时、预算与 PCP 清单；
- 使用 DeepSeek 官方公开文档核对当前模型标识、计费方式、缓存用量字段和公开价格；
- 产出研究报告和 Proposed 方案；更新就绪清单与项目状态为“提案已形成，未关闭”。

## 禁止范围

- 获取/使用账号、Key、真实账单或真实学生数据；调用真实 API 或任何模型；
- 修改供应商账号、充值、费用上限、学校财务制度、真实告警配置或数据库；
- 把公开单价乘法结果称为真实账单；把 DeepSeek 当前模型别名称为永久固定权重版本；
- 在学生内容、日志或 Artifact 保存提示词/回答正文。

## Proposed 规则

1. 每次调用前，按当前登记的峰时单价估算最坏请求费用并原子预留；缓存优惠不能用于扩大可用额度。
2. 对输入长度、输出上限和价格版本设硬边界；如果账本无法计算安全预留则默认拒绝。
3. 响应仅保存供应商返回的模型 ID、请求关联 ID、输入命中/未命中 Token、输出 Token、价格版本、人民币估算额和状态，不保存内容文本。
4. 供应商账户的实际扣费凭据（明细/账单/余额变化记录）作为对账来源；接口用量只用于预估和交叉核对。公开文档没有证明存在可供本项目调用的账单 API，具体来源需在获得正式服务账号后确认。
5. 派发后超时/断连进入待对账并继续占用预留，直到人工或已核验的供应商账单对账流程关闭。
6. 100 元/月硬上限覆盖本项目账号的全部使用；如果同一供应商账号被其他系统共用，必须先证明能按项目准确分账，否则不得真实启用。
