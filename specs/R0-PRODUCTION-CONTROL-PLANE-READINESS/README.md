## 1. 目标

在 ADR-010 的部署顺序第 2 步开始前，产出一份可逐项判断“是否就绪”的生产控制面前置清单，覆盖身份、数据最小化、关系数据库、托管密钥服务、持久预算账本、日志保留与审计、ECS 部署前置七个域。

本任务只产出文档与清单，不执行部署、不创建云资源、不接触任何真实凭据或真实数据。

## 2. 允许范围

- 只读审计现有规格、ADR、`CURRENT_STATE.md` 与已有 ECS 就绪记录。
- 新增一份 Proposed ADR（ADR-013）。
- 新增本规格。
- 新增一份 Proposed 威胁模型。
- 新增逐项含 Owner、证据、停止条件的就绪清单与验证报告。
- 运行只读验证命令：`git diff --check`、文件存在性与哈希计算、权威文档一致性检查。

## 3. 禁止范围

- 连接 ECS、执行任何远程命令、开放或探测端口。
- 创建、索要、粘贴、生成或存储任何 API Key、AccessKey、密码、私钥或凭据引用明文。
- 使用任何真实学生、教师或学校数据；接入真实身份系统。
- 部署、安装服务、创建 systemd 服务、配置反向代理或 TLS 证书。
- 修改现有权威文档、现有工作流、现有代码或现有 ADR 的既有条款。
- 进行真实模型调用或任何出网请求；产生任何费用。
- 选择供应商、数据库产品、密钥服务产品或身份方案（这些属于项目负责人决策）。

## 6. 停止条件

出现下列任一情形，立即停止对应项并向项目负责人提出简洁问题，不得自行假定或代替决定：

1. 需要真实云账户权限、计费账户或 AccessKey。
2. 需要选定或开通托管密钥服务、密钥轮换与撤销策略。
3. 需要学校身份系统、账号来源或租户边界的接入方式。
4. 需要决定费用所有者、价格版本、对账方式或额度提升。
5. 需要决定数据保留期限、删除/退出路径、研究授权或去标识化标准。
6. 需要决定域名、TLS 证书、网络入口范围或合规要求。
7. 任何请求要求连接 ECS、开端口、粘贴凭据或使用真实数据。

3. `git diff --check`；

5. 完成报告，明确 PASS / PARTIAL / FAIL 与未完成项。
