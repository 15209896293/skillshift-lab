# SkillShift Studio R0 质量规范

## 状态与效力

- 状态：**Active**（2026-09-24）；R0 Foundation Spike 与后续单一闭环的质量、测试、安全和数据边界。标记为 Proposed 的技术/治理选择仍须在相应 ADR 和证据中确认。
- 上游：`../product/REQUIREMENTS_SPEC.md`、`../architecture/TECHNICAL_SPEC.md`、`../product/R0_RESEARCH_TASK_EVIDENCE_CONTRACT.md`。
- 边界：本文件不把测试通过等同于学习效果、研究结论、真实学生安全或正式课堂可行性。

## 1. 实现与契约规范

- 每个功能必须映射到需求 ID、验收条件和最小证据；聊天记录、模型回复或截图不构成唯一完成证据。
- Web、API、Node、Workspace Provider、Agent Runtime、事件和 Manifest 必须通过版本化契约连接；不得依赖未声明的本机路径或前端临时状态。
- Node 不保存模型 API Key、长期明文令牌、真实凭据或无关个人数据。
- 所有本机路径、命令、环境变量、Artifact、事件 payload 和同步批次均在 Node 和服务端分别校验；不得只信任浏览器或 API 请求。
- 事件只能追加；纠正通过新事件或明确状态迁移表示。状态、事件、Artifact 和验证器必须具有稳定 ID 与版本。
- 权限边界、命令/网络策略、Provider、事件 Schema、数据分类或保留规则变化前，先更新 ADR、需求/技术规范和对应测试。

## 2. Node 与受限执行安全

### 2.1 必须遵守

- 一个 Node 只访问当前会话被允许的任务和绑定 Workspace；每个 Workspace 有独立根目录、非管理员运行身份和资源限制。
- 路径规范化后仍须位于 Workspace 根目录；拒绝绝对路径、`..`、符号链接绕过、其他 Workspace、私人目录和未批准环境变量。
- 命令执行必须记录 cwd、调用方、允许原因、超时、输出上限、退出状态、进程树和错误；未知命令默认拒绝。
- 网络、依赖安装、Git 操作和子进程必须由任务/Provider 策略显式允许；Foundation Spike 默认不接受任意依赖、任意网络或任意项目。
- 停止/接管应终止可追踪进程树；无法确认时状态必须为 `STOP_UNCONFIRMED`，不得伪报停止或成功。
- 不以“过程治理”为由收集全桌面截图、私人目录、无关进程、键盘记录、浏览历史或手机活动。

### 2.2 当前安全限制

`LocalRestrictedProcessProvider` 只面向合成任务或负责人确认有权处理的示例。未通过独立安全审计前，不接收任意外来项目，不承诺恶意代码隔离，不面向真实学生数据或公网多用户部署。

## 3. 提交包、数据与隐私

- 本机工作目录默认不整体上传；服务端只接收任务允许的 Artifact、Manifest、必要验证结果、事件引用和元数据。
- 所有 Artifact 上传前检查路径、大小、类型和敏感内容风险；疑似密钥、凭据或未允许数据不得进入事件 payload 或教师界面。
- Node 同步事件需带注册会话、Node 版本、schema 版本、单调序列和幂等标识；服务端防重放、拒绝错误任务/身份，并显示同步冲突与缺失。
- 教师只能查看与其任务和角色相关的提交包；学生只能查看自己的证据、反馈和补正状态。
- 教学运营数据不自动成为研究数据；研究导出需要独立目的、授权、最小化、去标识化、版本冻结和保留/退出处理。
- 未确认的保留期限、加密方案、学生删除权、导出审批和灾难恢复必须在 ADR-003 中保持 Proposed，不能被实现默认替代。

## 4. 分层测试规范

| 层级 | 最小验证 |
| --- | --- |
| Static | Web、API、Node、共享契约的格式、类型、依赖和 schema 检查。 |
| Unit | 状态迁移、权限判断、路径规范化、命令策略、事件构造、Manifest 哈希和待复核理由。 |
| Integration | Node 注册、任务加入、Workspace 绑定、受限命令、Agent Adapter、验证器、事件同步和提交包。 |
| E2E | 合成 Python 任务的创建—协作—验证—提交—复核—补正，以及暂停、停止、接管和恢复。 |
| Security | 越界路径、符号链接、跨 Workspace、重放/篡改事件、无效 Node、超时、输出过大、停止失败、凭据泄露。 |
| Recovery | 断网、Node 崩溃、重启、同步重试、版本不兼容、环境失败和未确认停止。 |

### 4.1 必测负向路径

1. `../`、绝对路径、符号链接及等价路径绕过；
2. Agent 在停止/接管后继续调用工具或其子进程继续运行；
3. 命令超时、非零退出、输出过大、磁盘/权限不足、Provider 不可用；
4. 跨任务、跨学生、跨 Workspace 读取事件或 Artifact；
5. Node 事件重放、乱序、重复、缺失、错误版本或伪造会话；
6. Artifact 含密钥、隐私内容、不允许路径或哈希与内容不一致；
7. 复核理由未显示事实/边界，或被错误解释为作弊/能力结论。

## 5. R0 证据与完成门槛

每次 Spike 或 R0 演示至少保存：冻结的合成任务版本、验证器版本、Node/运行环境版本、初始失败或任务起点、Agent/人工动作时间线、停止/失败路径、最终验证输出、提交包 Manifest/哈希、事件导出和已知限制。

一个功能只能标为 `Verified`，当且仅当：

1. 需求和验收条件可追溯；
2. 对应静态、单元与必要集成/E2E 测试通过；
3. 至少一条相关失败或安全路径被验证；
4. 权限、路径、事件和数据边界可定位；
5. Artifact、Manifest、运行和版本证据可复核；
6. 文档、ADR、限制和风险同步；
7. 没有未解释的高风险回归。

没有真实运行证据时，只能称 `Planned` 或 `Implemented`，不能称 `Verified` 或 `Done`。
