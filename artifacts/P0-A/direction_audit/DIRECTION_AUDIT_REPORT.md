### 1.3 固定 PASS 的真正含义

已复核的 `static_contract_check.py`、`verify_tsv.py`、三个 Python 输出验证器和 `verify_evidence_manifest.py`，支持的只是：当前文件集完整性、当前输出与仓库内预期文件的一致性，及部分静态结构条件。哈希一致只说明文件没有偏离该清单；它不证明来源真实性、运行日志真实性、预期值语义正确或学习效果。

`verify_diagnosis.py` 仅读 `candidate_diagnosis.md`，检查六个固定词/数字（含 `one-to-many`、`count`、`250.00`）。它会遗漏“关键词齐全而因果错误”的诊断，也可能拒绝术语不同但逻辑正确的解释。因此这是**验证器构念效度风险**，不是学生能力的反证。后续若获授权，应将其改为独立规格、结构化证据、错误/合理替代答案集、隐藏变形和盲评量规；本轮不修改验证器。

### 1.4 MySQL 账户偏差的安全与结论边界

脚本创建带 `MYSQL_ROOT_PASSWORD` 的临时容器、以 root 建 schema、导入夹具、运行 `candidate_submission.sql`、`candidate_q*.sql` 与 `candidate_queries.sql`，最后停止容器。合同却规定“fresh schema and task user”“non-privileged task user”，P0A-PUB-002 还将夹具描述为 fresh read-only fixture schema。

这说明当前证据可用于检查固定 SQL 的结果/数据库状态，不可用于声称：

- 学生提交在非特权权限下能运行；
- 任务限制可阻止 DDL、越权读取或破坏性命令；
- read-only 夹具或最小权限的安全条件已被执行；
- 真实的受限学生路径与 root 审计路径等价。

一次性容器降低了残留风险，但不替代权限验证。该偏差应列入未来实验工具的安全验收项；在独立授权和安全设计前，不运行/改写脚本。

## 2. 公开任务、适用性和用户研究的三条证据线

它们可以并行准备，但不能互相替代：

| 证据线 | 无需本地材料可继续什么 | 能支持什么 | 不能声称什么 |
| --- | --- | --- | --- |
| 公开可归属任务的方法研究 | 筛选有链接、版本/环境/目标的公开 SQL 任务；设计独立 contract、oracle、变形夹具、负例与验证器审查。 | 一种研究方法和任务设计是否可复核；公开任务模式是否存在。 | 对本校课程、学生或真实课堂适用。 |
| 本地适用性验证 | 在用户提供本地题目/评分规则后比对目标、环境、难度和设备；教师认可的公开等价任务也只能作局部适用性线索。 | 任务与当地课程/环境的匹配程度。 | 自主需求、学习效果或市场需求。 |
| 真实需求与学习效果研究 | 仅在另行授权后准备同意、访谈、可行性试用及正式研究方案。 | 参与者的实际障碍、愿意尝试/再用、能力或效果证据。 | 未参与学生、其他学校或长期职业能力。 |

因此，本地任务或教师认可公开任务不应成为所有研究工作的硬门槛；它们是**本地适用性**主张的前提，不是公开任务方法研究的前提。真实参与者材料才是需求和学习效果主张的前提。

### 3.3 相对廉价替代方案

“现成练习环境 + 通用 Agent + 清晰验证清单”应作为**主要比较基线之一**，不是已被击败的反证。现有工具确实可提供环境、Agent、测试及反馈；这使“再做一个练习平台”的价值主张缺乏支持。候选结构化训练可能值得研究的增益包括：是否能促成可审查的证据链、在未见 schema/业务规则上正确接受/拒绝/修正建议、以及更低的误判率。是否存在这些增益，目前没有证据。

## 4. 最小实验工具与研究设计

### 4.1 可设计但尚未实施的实验工具

完整平台暂停不妨碍**纸面/规格设计**一个研究必需的最小工具。其边界应仅是：

- 输入：版本化公开任务、夹具、独立 oracle、Agent 配置快照、正确/错误/信息不足建议包；
- 流程：展示一个任务与 Agent 建议，要求参与者标注接受/拒绝/修改/需补证，并提交可定位的验证依据；
- 输出：确定性结果、结构化理由字段、任务版本和最小事件记录；不采集无关聊天、完整桌面、私有文件或凭据；
- 验证：任务作者与 oracle/验证器审查者分离；已知错/对/合理替代答案都须测 false accept 与 false reject；
- 非目标：不做账号体系、课程管理、个人节点、多环境调度、长期画像、自动成绩或通用 Agent 平台。

本轮仅有设计建议，没有创建工具。任何实现、托管、调用模型、使用日志或学生试用均须另行授权和隐私审查。

### 4.2 将流程可行性与效果估计分开

| 阶段 | 目的 | 合理设计 | 不能得出的结论 |
| --- | --- | --- | --- |
| A：无参与者的方法准备 | 用公开可归属任务审查合同、oracle、变形、量规和替代方案。 | 文件级/独立审查，不接触学生。 | 本地适用、需求、学习效果。 |
| B：流程可行性试用 | 检查说明是否理解、设备/时间/隐私障碍、任务是否可完成、记录能否安全收集。 | 获授权后的少量自愿参与者；一人只经历一种主训练流程，收集质性障碍和完成情况。 | 训练有效、组间差异、无效结论。 |
| C：效果估计 | 比较普通 Agent、Agent+清单、候选结构化训练在迁移任务上的表现。 | 先定义最小重要差异、主要结果、样本量依据、随机/分层规则、盲评与模型快照；优先平行组或分批队列。 | 用小样本“无显著差异”证明无效果。 |

先前写入的“6–10 次访谈”“12–18 名参与者”“至少 8 份完整记录”不是来自本项目功效计算或外部资源承诺，故**全部撤销为验收门槛**。它们只能作为协调时的资源估计：访谈数量由信息充分性、异质性和可用时间决定；可行性人数由可招募人数、设备位和安全审查决定；正式效果样本在预先规定最小重要差异、方差和流失假设后计算。没有这些依据，不报科学样本阈值。

三条件 A/B/C 的交叉设计存在不可逆学习、顺序和携带效应：学生经历一种训练后已改变，不能把其后三条件表现视为独立处理。因此不采用“六种顺序各至少两份”的要求；该要求若用于每人完整经历 ABC，至少需要 12 名完整参与者，且仍不能消除污染，与先前“至少 8 份记录”也在算术和设计上不一致。若必须用交叉，仅可作为非因果的任务格式/可用性探查，使用全新等值题、足够 washout 并明确不估计训练效应；不作为 C 阶段主设计。

迁移测量必须同时包含：错误建议被正确识别、正确建议未被误拒、信息不足时提出补证、以及新 schema/规则下的独立验证。人工植入错误要标为训练材料，不可叙述为现实 Agent 错误频率。点击数、对话长度、关键词命中仅是解释线索，不是能力分数。

## 5. 挑战杯与个人成长

官方规则页与公开 2025 章程可支持：当届范围内包含在校专科生，成果时间、校内公示/审核及作品类别存在要求，且 AI 代写论文/调查报告有严重违规风险。未来届次通知、个人学籍/作者贡献、学校名额、类别和评审要求均**待核实**；不锁定科技发明制作 B 类，不预测获奖。

对大数据技术专科学生而言，当前可积累的真实能力是：SQL 粒度和数据质量判断、独立验证器/夹具设计、实验设计、版本与证据解释、清楚说明限制。它比“让 AI 完成平台”更可讲清；但尚不能证明已有竞赛竞争力。
