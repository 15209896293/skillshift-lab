# ADR-012 合成控制面持久化契约

## Status

Accepted（2026-09-24；项目负责人授权继续 R0 开发；不授权真实身份、真实数据、真实模型调用或部署）。

## Context

ADR-011 的网页原型仅在内存保存任务，重启后无法回放；ADR-009 的预算许可也仅是进程内测试对象。ADR-010 已要求真实多用户控制面具备持久关系数据与预算账本，但尚不能配置 ECS、托管密钥服务或真实数据库。

需要先验证两个不会触及真实用户的底层事实：任务最小提交可追加保存并按命令幂等重放，以及有限合成预算预留可跨进程重新打开数据库后维持硬上限。

## Decision

1. 建立一个**仅限合成范围**的 SQLite 持久化契约。SQLite 仅用于本机事务与重放验证；它不选择生产数据库。未来控制面以可替换关系数据库适配器实现同一契约。
2. 每个保存的 Manifest 必须声明 `synthetic-task-only`，使用固定合成范围，并以 `command_id` 幂等化。相同命令和相同内容返回原回执；相同命令配不同内容必须拒绝。历史快照不可覆盖。
3. 持久预算预留使用数据库事务与固定 100 元/月上限；只能处理合成 DeepSeek 探针的“预留”事实，不执行请求、扣费、结算或供应商对账。
4. 该契约只接受不可识别的合成范围和角色标识；拒绝真实身份字段及明显的凭据字段。它不是认证、授权、租户隔离、加密、保留/删除或生产审计方案。
5. 存储路径必须由调用者显式传入；禁止默认创建项目数据库、读取环境变量、记录模型 Key 或连接外部网络。

## Consequences

- 可证明基础持久化语义、冲突拒绝与并发预算上限，但不可声称已经具备生产数据库、实际账本或真实多用户安全。
- 当开始真实身份、真实学生数据、ECS 数据库、托管密钥、真实 DeepSeek 调用或数据保留配置时，必须建立新的规格、迁移方案和部署审核。
