# ADR-013 生产控制面就绪门禁与前置清单

## Status

Accepted（2026-09-24；项目负责人确认）。本门禁不授权部署、开端口或配置凭据；它明确要求所有前置项关闭后才可进入部署步骤。

## Date

2026-09-24

## Context

ADR-010 已选择现有 ECS 作为未来 R0 平台控制面的首个部署目标，并固定了部署顺序：本地 API 契约与安全测试 → 服务身份/密钥服务/持久账本配置 → 仅合成 DeepSeek 探针 → 监控与费用核对 → 再讨论教师界面、身份与非计分试用。

ADR-011 与 ADR-012 只验证了本机合成网页交互与 SQLite 合成持久化契约，两者都明确不是生产数据库、身份、授权或部署证据。ADR-008 与 ADR-009 建立了默认拒绝的真实调用接缝和 100 元/月本地预算许可，但都不是实际账本。

当前事实是：没有生产身份与租户、没有关系数据库、没有托管密钥服务、没有持久可对账的预算账本、没有日志保留与审计方案、没有网络入口与 TLS、没有 CI/CD，也没有真实教师或学生流程验证。现有 ECS 只完成了安全初始化（仅 22 端口、仅公钥登录、UFW 默认拒绝入站、fail2ban SSH jail、控制面目录已创建），未部署业务端口、数据库、Docker 或任何密钥。

问题：ADR-010 的第 2 步“服务身份/密钥服务/持久账本配置”缺少一份可逐项判断“是否就绪”的前置清单。没有这份清单，“当前测试通过”容易被错误外推为“可以部署”。

## Decision

1. 在 ADR-010 部署顺序的第 2 步开始之前，必须先关闭本 ADR 定义的生产控制面就绪前置清单（ID 前缀 `PCP-`）。任一项未关闭时，不得部署控制面、不得开放业务端口、不得进行真实模型调用、不得接入真实身份或真实学生数据。
2. 就绪清单固定覆盖七个域：
   - A 身份与租户；
   - B 数据最小化与数据边界；
   - C 关系数据库；
   - D 托管密钥服务；
   - E 持久预算账本；
   - F 日志保留与审计；
   - G ECS 部署前置。
3. 每项前置必须同时具备 Owner、可复核证据和停止条件。证据不得是聊天记录、截图、运行成功提示或“测试通过”本身；它必须是可定位的文件、命令输出、配置快照或独立验证记录。
4. 现有 ECS 的安全初始化是部署前置的**必要但不充分**条件。它不证明身份、数据、密钥、账本、保留或网络入口已经就绪。
5. 本 ADR 只定义门禁与清单，不选择供应商或产品、不创建任何云资源、不连接 ECS、不索要、粘贴或存储任何凭据、AccessKey 或 API Key、不修改现有工作流。
6. 当推进任一项需要真实云账户权限、托管密钥服务、学校身份系统、费用决定或数据保留决定时，停止该项并提请项目负责人作出简洁决策，不得自行假定或代替决定。
7. 控制面边界继续适用 ADR-010：ECS 只承载平台 API、模型网关、预算许可、任务/提交元数据和教师 Web 后端；它绝不运行本地大模型、任意学生代码、学生 Workspace、浏览器自动化或通用 Shell。

## Alternatives Considered

1. **直接把当前本机原型部署到 ECS，用部署过程发现问题。** 会把身份、数据、密钥、账本、保留与运维风险混在一处，无法形成可归因的证据，且违反 ADR-008/ADR-009 的默认拒绝边界。
2. **只沿用 ADR-010 的顺序，不建独立清单。** 顺序描述的是阶段，不是可验收项；缺少逐项 Owner、证据和停止条件时，“就绪”无法判断，也无法审计。
3. **先做真实合成探针，再补身份与账本。** 违反 ADR-008 第 1 条（真实调用必须同时具备凭据解析与已发放预算许可）和 ADR-009 第 5 条（替换为持久账本前不得真实调用）。
4. **用第三方托管平台整体替代自建控制面。** 会改变数据边界、费用模型与保留责任，属于独立决策，不能由本 ADR 或工程任务替代。

## Consequences

- 可以逐项判断控制面是否就绪，并让“未就绪”保持可见，而不把本机契约测试外推为部署准备度。
- 关闭清单需要真实云账户权限、学校身份来源、费用与数据保留决策，预计跨多个独立任务，且部分项在项目负责人决策前无法推进。
- 总体 Gate B 仍为 PARTIAL；本 ADR 不改变任何既有 Gate 状态，也不产生新的已实现能力。
- 不引入运行时依赖、不修改现有代码或工作流、不产生费用。
- 新增一份 Proposed 威胁模型作为清单的安全依据；它同样是 Proposed，不能被当作已验证的安全承诺。
