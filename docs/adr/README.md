# Architecture Decision Records

This folder records important architecture decisions and why they were made.

Use ADRs when a decision is expensive to reverse, affects multiple modules, or changes product/research boundaries.

## Status Values

- Proposed
- Accepted
- Superseded
- Rejected

Most early SkillShift decisions should start as Proposed.

Do not mark a decision Accepted unless the product owner confirms it.

## Candidate ADRs

- Web-first Student Client
- Control Plane / Execution Plane Decoupling
- Managed Sandbox with optional Personal Node
- Agent Gateway
- Hidden Verifier Independent Execution
- Operational / Research Data Plane Separation
