# ADR-011 本机合成网页原型边界

## Status

Accepted（2026-09-24；项目负责人已授权继续长线开发，但不授权部署、真实账号、真实数据或真实模型调用）。

## Context

Gate A 已证明教师创建、学生引导、提交、复核和补正的确定性领域工作流可以运行，但它只有 Python 演示和测试，尚没有教师或学生可操作的界面，也没有可验证的 API 边界。现有 ECS 被 ADR-010 选为未来控制面候选，但当前未配置密钥、数据库、身份、业务入口或部署条件。

在这些条件具备前，直接把网页部署到 ECS 会把产品交互、真实数据、账号权限和运维风险混为一处，无法形成清晰证据。

## Decision

1. 先实现一个仅供本机演示的网页原型：教师和学生各有一个可操作视图，均调用同一个本机 JSON API。
2. 服务端复用 Gate A 的 `EducationWorkflow`、固定合成模板和 `ScriptedGuidanceAdapter`；只使用 Python 标准库，不增加外部依赖、不调用外网或模型运行时。
3. API 仅接受固定合成角色 `teacher-demo` 和 `student-demo`，且只在进程内保存数据。它们不是登录、认证、授权或多用户方案；进程重启后数据清空。
4. 本机演示服务默认只绑定 `127.0.0.1`。不得将其暴露到局域网或公网，不得连接 ECS。
5. 网页必须清楚标明“合成演示”，不得显示或收集真实姓名、学号、模型 Key、密码、私钥或 AccessKey，也不得输出评分、作弊、能力或外部 AI 结论。
6. 未来走向 ECS 前，必须另行完成生产 API、身份与租户、持久数据、保留期限、服务端授权、托管密钥、持久预算账本、监控和部署审核。ADR-010 的先后顺序保持有效。

## Consequences

- 可以验证教师和学生在同一闭环中的实际页面操作与 API 状态，而不对真实用户或供应商产生影响。
- 该原型不能证明真实课程可用性、登录安全、数据持久性、多用户并发、模型质量、成本控制或部署准备度。
- 服务端接口和静态前端可作为未来正式架构的可替换交互参考，但不能直接作为生产控制面发布。
