## 当前应如何使用计划书

1. 需要快速理解全项目目标、研究主线、Studio 边界和阶段安排时，阅读当前唯一总体计划书。
2. 需要决定“现在开发什么、不开发什么”时，优先读 [`PROJECT_ALIGNMENT_2026-10-17.md`](PROJECT_ALIGNMENT_2026-10-17.md)、Active R0 决策和任务规格，不以计划书替代它们。
3. 需要判断“是否已经实现或验证”时，只看带日期的 `artifacts/`、测试记录和当前重跑结果；计划书、路线图和架构草案均不构成实现证据。
4. V1.0、V2.0、V2.2、V3.0 及融合前计划书均为来源/历史材料，保持原样；若项目方向发生变化，应新增带日期的决策、研究协议或路线图，并按治理规则更新现行计划，不回写来源材料制造“当时已知”的假象。

- Git 当前将 V2.0、V2.2 根目录旧路径显示为删除，而归档目录存在同内容副本；这是待负责人确认的归档迁移记录，不是可自动清理的文件。
- V3.0 中的长期 Workspace、执行与产品形态内容，必须以 Active R0 的执行关闭边界和产品重定位决策重新审视。
