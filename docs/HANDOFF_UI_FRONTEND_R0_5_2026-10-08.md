## 1. 先回答形态问题：当前开发的是 Web

当前交接范围是**浏览器 Web 应用**。教师端和学生端通过浏览器使用；本地 Workspace API/WSGI 是合成原型的服务端入口。现有工程没有因此变成桌面软件，也没有确定要用 Electron、Tauri 或其他桌面容器。

前端和服务端代码可以继续放在同一个 Git 项目中，按目录和接口分层，不需要拆成两个仓库。现有相关路径：

| 路径 | 当前用途 |
| --- | --- |
| `apps/teacher-web/` | 既有教师流程验证网页 |
| `apps/student-web/` | 既有学生流程验证网页 |
| `apps/agent-first/web/` | Agent-first 合成 Harness 的网页 |
| `apps/workspace-client.mjs` | 共享 Workspace API 客户端契约 |
| `apps/agent-first/agent_first/` | 本机合成 API/WSGI 等服务端代码 |
| `apps/student-studio/` | 隔离执行研究切片；不是已通过安全 Gate 的学生运行环境 |

R0.5 目标是形成更成熟的教师 Web 与学生 Web 工作体验。既有页面是流程验证资产，不应默认作为新 UI 的最终视觉基础；保留现有页面和服务端契约，除非负责人另行明确范围。新 UI 的目录、构建工具与组件框架尚需工程师先盘点后提出最小方案，不能仅凭本交接擅自大规模迁移或重构。

## 2. 项目现状与证据边界

2026-10-06 的 Golden Path 交接记录：本机合成教师—学生控制面有创建/发布、学生选择/开始/提交、教师复核/补正等流程；旧网页不是 Studio 目标 UI。该交接记录的测试结果是历史快照，不是本次重跑结果。当前工作区存在大量已修改和未跟踪资产，另有历史文档在 Git 状态中显示删除；开始实现前必须重新查看 `git status --short --branch` 并保护这些内容。

当前已接受的产品方向允许探索项目型工作空间和代码文本编辑体验，但不等于下列能力已实现或获准：真实登录、真实模型调用、生产持久化、真实学生数据、任意文件访问、Shell/依赖安装、运行学生代码、部署或正式研究数据收集。界面若展示尚未接通的能力，必须清楚标为演示/模拟状态，不得让模拟结果看起来像真实运行证据。

## 3. 本次交接的目标

只围绕一条候选 Golden Path 设计并实现 Web 前端 Mock：

> 教师创建并发布一个合成 Python/CSV 数据清洗与异常诊断任务；学生进入该任务工作台，查看任务材料、Agent 协作区、产物/差异和验证状态，补充自己的判断并提交；教师查看任务相关提交证据，认可或要求说明、补证、补正；学生回应后完成一次约束变化的迁移任务。

这是前端产品切片，不是完整平台开发。首轮目标是页面结构、交互路径、状态表达和响应式表现可评审；Mock 阶段不连接真实模型、生产 API、真实身份或学生数据。

## 4. 第一轮页面范围

第一轮仅覆盖四个核心页面，分别有明确角色和任务：

1. **学生首页**：查看当前课堂任务入口、状态和下一步；个人 Agent 与课堂任务入口在信息架构上区分，暂不实现个人记忆算法。
2. **学生项目工作台**：任务说明与材料、项目文件/代码文本视图、Agent 对话/建议、学生确认/拒绝/接管动作、验证结果、说明与提交入口。代码运行未通过安全 Gate，不得提供可用的真实运行按钮；若为展示流程出现验证结果，须标明合成/模拟。
3. **教师 Agent 任务设计器**：配置任务目标、输入材料、交付物、学生责任、验证要求、截止时间和发布预览。任务级 Agent 权限编排与现行 Active R0 文件存在决策差异，详见第 6 节；页面不得自行把未决方案做成已生效产品能力。
4. **教师复核与补正工作台**：查看队列、提交物、验证/过程摘要和不可观察边界；支持认可关闭、请求说明、请求补证、请求补正、标记环境问题等已有工作流动作。每个动作都需呈现理由和后续状态。

页面必须考虑可见状态：加载、空列表、失败与局部重试、无权限/不可用、验证未通过、等待复核、要求补正、补交、关闭。至少选取一条正常路径和一条失败/补正路径走通原型。不要只交付理想成功截图。

### 前端交付物

- 可本地运行的 Web Mock 纵向切片；
- 四页之间至少一条教师发布→学生完成/提交→教师补正→学生回应的可演示路径；
- 一个验证失败或环境故障的可演示路径；
- 清楚标记的模拟 Agent 与模拟验证结果；
- 启动说明、Mock 场景说明、已知限制和实际运行/检查证据；
- 最终 diff 摘要，并确保现有用户资产未被覆盖。

### 验收标准

- 页面和导航明确表达教师 Web 与学生 Web 的角色边界；
- 主流程与失败/补正流程均可从界面理解并演示；
- 任务状态与错误不会被成功样式掩盖；
- 四页在约定桌面与窄屏视口下可用，无明显溢出或关键操作丢失；
- 所有模拟数据、模型行为和验证结果都能被用户识别为模拟；
- 没有未授权的模型、代码执行、数据采集、后端架构或部署范围扩张。

UI/前端交付不等于 R0.5 Golden Path 通过，也不构成真实用户价值或教育效果证据。
