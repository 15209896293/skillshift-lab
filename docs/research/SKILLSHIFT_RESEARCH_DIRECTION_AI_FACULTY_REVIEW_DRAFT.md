# SkillShift 科研方向说明：Agent 参与职业任务后的人类能力、协作过程与迁移评价

> 目标读者：中国高校人工智能、自然语言处理、大模型、人机协作与智能教育方向教授  
> Task ID：`DOC-RESEARCH-DIRECTION-PROFESSOR-REVIEW-001`  
> 版本日期：2026-10-14  
> 阅读时间：约 10 分钟  
> 证据边界：本文提出的是待检验的研究问题与初步设计，不代表创新性、教育效果或职业价值已经得到验证。

## 摘要

SkillShift 是一个关于“AI Agent 参与职业任务后，人的专业能力结构及其形成方式如何变化”的长期研究设想。项目所关注的并不是“AI 是否影响教育”这一宽泛问题，也不是建设一个通用 AI 教学平台，而是一个更具体的测量与因果问题：**在真实或近真实职业任务中，Agent 的条件化能力边界、学习者已有的专业基础、人机协作中的验证与接管行为，以及后续能力迁移之间存在什么关系？**

本项目拟把研究对象分为四层：Agent 能力、人类基础能力、人机协作过程和能力迁移。四层不是并列模块，而是一条待检验的逻辑链：首先明确特定模型、工具和任务条件下 Agent 能做什么；其次测量人在没有或较少 Agent 支持时的基础能力；再次观察人在协作中如何判断、验证、修正和接管；最后通过更换数据、约束、环境或减少 Agent 支持，检验协作期间的高任务表现是否转化为可迁移能力。相应评价不采用单一完成率，而区分 Outcome（结果）、Process（过程）和 Transfer（迁移）。

SkillShift 与领域大模型能力评测、人机协作和 AI 辅助学习研究均有联系。其中，与刘贵全教授参与并担任共同通讯作者的 ChemEval，在“通过分层、细粒度任务识别模型专业能力边界”这一问题意识和方法上存在关联；但 ChemEval 主要评价化学领域大模型能力，SkillShift 拟进一步研究 Agent 进入职业任务后人的能力、协作机制和教育评价如何变化，两者研究对象和最终目标不同。与此同时，近年的职业任务 Agent 评测和 Human-Agent Collaboration 研究已经与 SkillShift 形成明显相邻关系，因此项目不能预设原创性成立。其潜在研究贡献必须通过更严格的概念区分、对照实验、迁移测量和职业效度证据来建立。

当前项目已有任务—协作—提交—教师复核—补正的本机合成流程原型，以及 Foundation—Agent—Transfer 的研究结构和数据边界设计；但尚未形成正式职业任务 Benchmark、真实 Agent 比较、人类受试实验、迁移效果数据或学校试点结论。就科研立项而言，项目目前更接近“问题框架和研究基础已初步形成，但核心构念、首个假设与实验识别策略仍需专家收敛”的阶段。

## 一、为什么提出这一研究方向

大模型及其 Agent 化应用正在进入软件开发、数据处理、数据库操作、系统运维和数字内容生产等专业活动。与只生成一段文本不同，Agent 可以读取任务上下文、调用工具、修改文件、执行多步骤操作并根据反馈继续行动。这使职业任务中的人机分工发生变化，但这种变化不能简单表述为“AI 替代了多少工作”或“学生应不应该使用 AI”。

传统职业教育通常以学习者独立完成任务为主要训练和评价方式。在 Agent 参与后，至少出现三个需要区分的事实：

1. 学生借助 Agent 得到了合格产物；
2. 学生在过程中能够识别约束、判断建议、验证结果、修正错误并在必要时接管；
3. 学生在改变数据、环境或工具条件后，仍能独立或以较少支持完成新任务。

第一项是任务表现，第二项是协作过程，第三项才接近能力迁移。它们可能相关，也可能分离。例如，Agent 可以显著提高即时完成率，却掩盖基础知识缺口；学生也可能频繁操作或反复提问，但并未形成有效验证能力。因此，只看最终答案、对话长度、调用次数或完成时间，均不足以说明学习或职业能力已经形成。

这一问题值得研究，主要不是因为 Agent “新”，而是因为现有评价对象正在变化。若 Agent 已经能够稳定完成传统实训中的若干操作步骤，那么原任务的高分可能不再支持原有能力解释；反之，若教育简单撤除 AI，又可能与真实工作方式脱节。更有意义的问题是：哪些基础能力仍然构成有效协作的前提，哪些新的判断与责任能力需要被训练，以及怎样的任务证据能够区分“借助工具完成”与“形成了可迁移能力”。

## 二、核心科学问题及其逻辑关系

### 2.1 建议聚焦的主问题

SkillShift 当前最适合聚焦的主问题是：

> **在受控的真实职业任务中，学习者的专业基础能力如何影响其对 Agent 输出的判断、验证、纠错与接管，并进一步影响即时任务表现和后续迁移表现？**

这个表述把项目从一般性的“AI 与教育”研究，收缩到三个可测量关系：基础能力是否是协作效果的前因；协作过程是否是基础能力影响结果的中介机制；迁移任务是否能区分短期增效与能力形成。

### 2.2 五个子问题

1. **Agent 能力边界问题**：在冻结的任务、模型、提示、工具权限和运行环境下，Agent 能稳定完成哪些任务步骤，在哪些步骤和条件下出现可复现失败？
2. **基础能力调节问题**：学习者已有的专业知识、问题分析和故障定位能力，是否影响其使用 Agent 后的增益幅度及错误暴露风险？
3. **协作机制问题**：验证覆盖、错误识别、建议修订和人工接管等行为，是否比最终完成率提供更多关于协作质量的解释？
4. **迁移问题**：Agent 辅助下形成的高表现，在更换数据、约束或环境，或撤除、减弱 Agent 支持后能否保持？
5. **评价效度问题**：Outcome、Process、Transfer 的组合，能否比单一结果分数更可靠地解释 AI 时代职业能力；这种解释在不同任务族中是否稳定？

### 2.3 逻辑框架

```text
任务结构与难度 ───────┐
Agent/模型/工具条件 ───┼──→ 协作情境
                       │
人的 Foundation 能力 ──┴──→ 判断、验证、纠错、接管（Process）
                                      │
                         ┌────────────┴────────────┐
                         ↓                         ↓
                 Agent 辅助任务结果          新情境迁移表现
                    （Outcome）               （Transfer）
```

其中，Agent 能力评测不是研究终点，而是人类实验的条件校准：如果不知道 Agent 在给定任务中何时正确、何时失败，就无法判断学生的接受、拒绝或接管是否恰当。迁移也不是附加测试，而是区分“即时任务增效”与“能力形成”的关键效标。最终的职业能力结构只能是实验结果，不应预先把 Foundation、Collaboration、Verification、Transfer 固化成已经成立的量表。

## 三、四层研究框架

### 3.1 AI 能力层（Agent Capability）

该层回答“在什么条件下，什么 Agent 能完成什么职业任务”。评价单位不是模型名称本身，而是“任务版本 × 模型版本 × 工具权限 × 环境版本 × 运行策略”。拟观察的内容包括：

- 任务总体成功率与多次运行稳定性；
- Execute、Diagnose、Adapt、Verify 等不同任务步骤的表现差异；
- 错误类型、失败位置、恢复能力和副作用；
- 工具权限、上下文、提示和环境变化对表现的影响；
- 成本、时延和人工复核负担等使用条件。

这一层可借鉴 ChemEval 的分层、细粒度和领域专家参与思想，也可参考真实计算机环境 Agent Benchmark 对环境状态和执行结果的验证方式。但 SkillShift 不应只形成一个模型排行榜。其主要作用是提供可复现的 Agent 条件和失败样本，为后续人机协作实验确定“可委托环节”“高风险环节”和“必须由人验证的环节”。

### 3.2 人类能力层（Human Capability）

该层测量学习者在没有 Agent 或 Agent 支持受到严格限制时的起点能力，至少包括：基础专业知识、任务建模与约束识别、故障定位、结果验证和必要的独立操作能力。

基础能力不宜只用课程成绩或自我报告代替。更合适的做法是使用与主任务同技能族、但不同实例的 Foundation 任务，并结合简短解释或故障诊断题。该层的目的不是证明“人必须独立完成所有工作”，而是建立后续分析所需的基线：不同基础水平的学习者，是否以不同方式受益于或受损于 Agent；Agent 是否缩小了结果差距，却扩大了理解或迁移差距。

### 3.3 人机协作层（Human-Agent Collaboration）

该层不只评价最终产物，而是关注学习者能否在关键节点保持有效的人类责任。主要研究行为可包括：

- 是否能够把任务目标、约束和验收条件表达给 Agent；
- 面对正确建议时是否能够有效采用，面对错误建议时是否能够拒绝或修订；
- 是否选择了与风险相匹配的验证方法，而非形式化点击“已检查”；
- 是否能解释错误原因并定位人、Agent、任务、验证器或基础设施中的问题；
- 当 Agent 无法继续或建议具有高风险时，是否能够接管任务。

这里的核心不是追求“更多人类操作”，而是研究适当依赖：正确采用可靠建议、拒绝错误建议，并在不确定时增加验证。对话数量、停留时长、复制粘贴或接受按钮本身均不能直接作为能力指标。过程指标必须与任务事实、Agent 建议的实际正确性和后续结果绑定，并尽可能由确定性验证器与独立人工复核共同支持。

### 3.4 能力迁移层（Skill Transfer）

该层用于检验协作经验是否转化为学习者自身可以重新组织的能力。迁移任务可有三个梯度：

- **近迁移**：更换数据或参数，但保留任务结构；
- **中迁移**：改变约束、字段、故障组合或工具条件；
- **远迁移/延迟迁移**：在新的项目情境或一段时间后，以更少 Agent 支持完成相关任务。

迁移任务必须避免仅复现主任务步骤或记忆 Agent 输出。若 Agent 组只在有 Agent 时表现更好，撤除支持后不优于对照组，则当前证据只能支持“工具提高了即时表现”，不能支持“能力提升”。若过程中的验证、纠错和接管行为能够预测迁移表现，且这种关系在控制 Foundation 后仍存在，才有理由进一步讨论协作机制对能力形成的意义。

## 四、与相关研究的关系

### 4.1 与 ChemEval 的联系与区别

ChemEval 的 ICLR 2026 版本将化学能力组织为四个递进层级、十三个能力维度和六十二项文本/多模态任务，并通过领域数据、专家筛选和细粒度任务设计评测大模型与多模态大模型。[1] 对 SkillShift 最有启发的不是化学任务本身，而是三点方法意识：专业能力需要分层描述；任务应由领域知识和专家审核支撑；总分之外需要分析不同能力维度和失败边界。

二者的共同点包括：都关注大模型专业能力评价；都不满足于用少量通用题目或单一总分概括真实能力；都希望通过更细粒度任务理解模型在具体条件下的能力边界。

但两者不能被表述为同一研究路线。ChemEval 的主要评价对象是化学领域的模型能力，核心问题是模型在不同化学层级与任务中的表现。SkillShift 拟研究的是 Agent 能力进入职业任务之后，学习者的基础能力如何影响协作行为，以及协作结果能否迁移；其评价对象包括 Agent、人和人机系统，最终关心职业能力评价与教育任务设计。因此，较准确的表述是：**SkillShift 与 ChemEval 存在研究方法和问题意识上的关联，但研究对象和最终目标不同。** SkillShift 可以借鉴其专业任务分层与专家构题方法，却不能以 ChemEval 的模型成绩推断人的能力、协作质量或学习效果。

### 4.2 与大模型及 Agent 能力评测的关系

OSWorld 等工作把 Agent 放入真实计算机环境，以任务初始化、环境状态和可执行评价脚本检查完成情况，说明 Agent 评测正在从静态问答走向真实环境中的多步骤行动。[2] 这类研究支持 SkillShift 的“职业任务、运行环境和可验证产物”取向，也提示模型能力会随工具、环境和执行框架显著变化。

SkillShift 的差异不应建立在“任务更真实”这一笼统主张上，因为真实环境 Agent Benchmark 已经快速发展。更可能的研究空间是：把 Agent 的条件化能力数据作为人类实验的已知条件，进一步检验基础能力、协作行为和迁移之间的关系。换言之，Agent Benchmark 是研究的第一层和实验基础，而不是项目全部。

### 4.3 与人机协作研究的关系

Human-AI Collaboration 研究长期关注互补绩效和适当依赖。已有研究表明，提供 AI 解释不必然使人机团队超过单独的人或 AI；协作效果取决于人能否识别何时应依赖系统。[3] REL-A.I. 又进一步指出，人对语言模型的依赖会受到表达风格、交互语境等因素影响，仅评价模型校准或文本质量不足以解释实际依赖行为。[4] SPHERE 等工作则强调，人机系统评价需要同时说明评价对象、方法、参与者、时间点和有效性依据。[5]

SkillShift 与这类研究直接相邻：验证、纠错、拒绝和接管，本质上都涉及适当依赖和人类监督。项目需要避免把这些概念重新命名后当作创新。可能形成差异的地方，是在职业教育语境中把“先验基础能力—协作过程—无/弱辅助迁移”置于同一设计中，并研究其对职业任务评价重构的意义。

尤其需要注意，2026 年出现的 CollabSkill 已经直接以真实职业任务、真实工作人员和 Agent 配对研究 Human-Agent Collaboration，并尝试区分人和 Agent 的技能贡献。[6] 这项相邻工作显著提高了 SkillShift 的原创性门槛。若 SkillShift 只做“真实职业任务上的人机协作评分”，将很难形成清楚区分。项目必须说明自己是否聚焦学习者与能力形成、是否以 Foundation—Agent—Transfer 的纵向关系为主要对象，以及能否提供职业教育任务效度方面的新证据。

### 4.4 与 AI 辅助学习研究的关系

已有随机实验表明，工具提高练习阶段表现并不必然带来撤除工具后的学习增益。Bastani 等人在高中数学场景中区分了使用生成式 AI 时的练习表现和之后无 AI 考试的表现，并观察到无适当约束的 AI 使用可能产生二者分离。[7] 这为 SkillShift 的 Outcome—Transfer 区分提供了直接依据，但其结论不能未经检验外推到职业教育任务。

SkillShift 若只比较“使用 Agent”和“不使用 Agent”的任务完成率，基本属于既有 AI 辅助学习研究的场景延伸。要形成更明确的科研问题，至少需要增加两个部分：一是把 Agent 的错误结构和工具条件纳入实验，而不是把 AI 当作一个不可分解的处理变量；二是研究专业基础能力和协作行为如何解释迁移结果，而不是只检验平均处理效应。

## 五、初步研究方法

### 5.1 总体策略：真实职业任务实验，而非平台功能评价

SkillShift Studio 只承担任务呈现、Agent 条件控制、必要事件记录、产物提交和教师/研究者复核等研究基础设施功能。页面是否完整、功能是否丰富、模型是否先进，都不能替代研究设计。正式研究应以版本化职业任务和可复核实验协议为中心。

首阶段建议只选择一个任务族，例如当前材料中已经收敛的 Python + CSV 数据清洗与异常诊断；数据库导入、查询与一致性检查可作为第二任务族，而不应一开始同时覆盖数据库、软件开发、运维和数据工程。每个任务族需要由教师或领域专家确认职业关联，建立参考解、正负例、确定性验证器、常见失败类型和至少两套等价变体。

### 5.2 分阶段设计

**阶段 A：Agent 条件校准。** 在冻结环境中，对多个模型或同一模型的不同工具条件进行重复测试，获得步骤级成功率、失败类型和稳定性。该阶段确定哪些建议可作为正确样例、哪些错误可自然出现，以及哪些高风险错误需要人工构造的受控刺激。真实 Agent 运行与人为植入错误应分开报告。

**阶段 B：Foundation 基线测量。** 参与者完成同技能族但不同实例的低 Agent 或无 Agent 任务，测量基础知识、约束理解、故障定位和验证能力。基线任务不得与主任务完全相同，以减少练习效应。

**阶段 C：随机或准随机协作实验。** 最小设计可比较独立完成组与 Agent 辅助组；若样本和资源允许，可增加“无结构自由使用 Agent”与“要求显式验证/接管的结构化协作”两个 Agent 条件。分组应按 Foundation 水平分层随机，任务变体采用交叉或平衡分配。核心是固定模型版本、工具权限、时间、材料和任务难度，使 Agent 条件具有可解释性。

**阶段 D：迁移与延迟测量。** 在不使用 Agent、减少 Agent 支持或改变工具条件下完成近迁移任务；必要时增加延迟测验。迁移任务必须更换数据、约束或故障组合，并在实验前明确主要终点，避免看到结果后选择最有利指标。

### 5.3 Outcome—Process—Transfer 三维评价

| 维度 | 建议指标 | 解释边界 |
| --- | --- | --- |
| Outcome | 产物正确性、约束满足、鲁棒性、完成时间、成本 | 说明当次任务表现，不自动说明学习发生 |
| Process | 正确建议采纳率、错误建议拒绝率、验证覆盖、错误定位、修订质量、接管时机 | 需要结合建议真实正确性和任务语境，不能用日志数量代替能力 |
| Transfer | 新数据/新约束任务正确性、无或弱辅助表现、延迟保持、解释与故障恢复 | 才能部分支持能力形成，但单次迁移仍不等于稳定职业胜任力 |

数据库任务可以形成如下实验实例：实验组使用 Agent 完成数据导入、查询和一致性诊断，对照组独立完成；系统和人工共同记录结果正确性、时间、错误类型、Agent 建议、验证行为和接管行为；随后两组在字段变化、约束变化或故障原因变化的新数据库任务中，以无 Agent 或弱 Agent 条件完成迁移测试。若 Agent 组只在第一任务更快，迁移任务没有优势，则结论应限于即时增效；若 Foundation 与验证行为能够解释迁移表现，才进一步讨论能力机制。

### 5.4 分析与效度控制

- 研究问题、主要终点、排除规则和分析方法宜预注册；样本量由功效分析决定，不在本稿中预设。
- 分析可使用参与者和任务的多层模型，检验 `Foundation × Agent 条件` 的交互，并探索 Process 是否具有中介作用；中介解释需要满足时间顺序和稳健性条件，不能仅凭相关性命名因果机制。
- 任务、模型、提示、工具、环境、验证器和数据均需版本冻结；模型更新后应作为新条件复测。
- 自动验证优先覆盖客观产物和环境状态；解释、诊断和接管质量由经训练的人工评价者独立评分，并报告一致性与分歧处理。
- 对外部 AI 使用、同伴帮助、设备故障和缺失数据制定事先规则；基础设施故障不得被计为学生能力不足。
- 仅采集任务所需数据；运营数据进入研究分析前需独立授权、去标识化、数据字典、访问与退出机制。

## 六、当前研究基础与尚未形成的证据

截至本稿形成时，项目已有的基础主要是：职业任务单元、Foundation—Agent—Transfer、Outcome—Process—Transfer、Task Graph、Evidence Contract 等概念草案；一个以 Python + CSV 为代表任务的收敛方向；以及教师创建/发布、学生协作/提交、教师复核/补正的本机合成流程和部分工程测试。这些资产可以支持任务协议与研究工具设计。

但以下事项尚未由当前证据支持：正式职业任务 Benchmark 已建立；真实大模型或 Agent 能力已比较；真实学生或教师已参与；学习效果或迁移效应已经观察到；教师负担、职业效度和跨任务可推广性已经验证；工程原型能够安全运行学生代码或进入正式课堂。现有合成流程只证明部分软件契约在限定条件下可工作，不能作为研究假设成立的证据。

因此，项目下一阶段不宜继续扩大平台功能，而应优先形成一个可由外部专家审查的最小研究包：一个任务族、一个核心假设、一套 Agent 条件、一组 Foundation/Agent/Transfer 等价任务、确定性验证器、人工评分规范、数据字典、预注册分析草案和伦理/隐私说明。

## 七、当前最大的科研疑问

当前最关键、也最可能决定项目是否值得继续投入的疑问是：**在控制学习者原有 Foundation、任务难度和 Agent 能力后，验证、纠错与接管等 Process 证据，是否能够对后续 Transfer 表现提供稳定的增量解释或预测？**

如果不能，SkillShift 可能只是把已有的 Agent Benchmark、传统前后测和教学流程放在同一个平台中，过程采集本身未形成新的研究价值。如果能够，而且这种关系能在等价任务、不同 Agent 错误和独立评价者下复现，项目才有依据进一步讨论人机协作能力的测量、职业任务评价重构及教学干预。这个问题应优先于扩展专业、增加平台功能或建立长期能力画像。

## 八、教授审稿视角下的主要科研风险

### 风险 1：可能只是已有 AI 辅助学习研究的职业教育版本

如果研究只比较有无 Agent 的完成率、时间和满意度，原创性较弱。需要提出并检验更具体的机制，例如 Foundation 如何调节错误识别和接管，Process 指标是否对 Transfer 有增量解释力。

### 风险 2：与 Human-Agent Collaboration 和职业任务评测的新工作重叠

CollabSkill 等工作已经直接研究真实职业任务中的人机协作。SkillShift 必须尽早完成系统文献审查，明确自己的独立变量、理论构念、主要终点和对照基线。不能以“真实任务”“细粒度”“人机协作”本身作为创新表述。

### 风险 3：任务表现与能力提升仍可能混淆

过程日志再丰富，也不必然证明理解。需要撤除或减弱 Agent 的迁移测试、延迟测量和独立解释任务；同时防止迁移任务过于相似，造成记忆复现。

### 风险 4：所谓能力变化未必具有职业意义

实验任务可能只反映课程练习或平台熟练度。任务应来自可追溯的职业标准、真实工作材料或领域专家判断，并检验任务内容效度；后续还需比较学校任务表现与真实或近真实工作表现之间的关系。

### 风险 5：研究范围过大

同时研究多专业、多模型、能力结构、教育干预、个人技能记忆和平台系统，会导致每一部分都缺乏足够证据。建议首阶段只回答“基础能力—协作过程—迁移”这一关系，并限定一个任务族。Agent Benchmark 只做到支撑实验条件所需的深度。

### 风险 6：过程指标可能缺乏构念效度

“点击验证”“拒绝建议”或“接管”既可能代表能力，也可能来自谨慎性、界面诱导或任务熟悉度。每个过程指标都需有反例、人工评分准则和与外部效标的关系，不能把可记录性误认为有效性。

### 风险 7：模型漂移、数据污染和外部工具使实验难以复现

在线模型持续更新，学生也可能使用平台外 AI。研究需要冻结条件、记录版本并对不可观察行为保持诚实；无法控制的部分应作为局限或敏感性分析，而不是通过过度监控解决。

### 风险 8：跨学科定位可能不清

如果论文面向人工智能领域，需要说明其技术或评价方法贡献；如果面向学习科学，需要更强的学习理论和因果设计；如果面向职业教育，需要职业效度与实施研究。项目很难在第一阶段同时满足三类学科的完整贡献标准，必须选择主要学术落点。

## 九、初步判断与建议收敛方向

从科研立项初审角度，SkillShift 所指向的问题具有现实性：Agent 的任务能力正在变化，而“模型能完成”“人机系统能完成”和“人形成了能力”确实不是同一问题。把 Agent 能力校准、人的基础能力、协作过程和迁移评价连接起来，有可能形成有意义的研究设计。

但当前还不能据此判断项目已经具有原创贡献。其价值取决于三项尚未完成的工作：第一，能否相对于 ChemEval、真实环境 Agent Benchmark、Human-Agent Collaboration 和 AI 辅助学习研究提出清楚的差异化命题；第二，能否把“验证、纠错、接管、迁移”等概念转化为有构念效度和可复核规则的测量；第三，能否在一个足够窄的职业任务族中获得可重复的人类实验结果。

建议将首篇研究或首个正式课题收敛为：

> **专业基础能力对 Agent 辅助职业任务中适当依赖与迁移表现的影响：以一个版本化数据处理任务族为例。**

这一范围允许 Agent 能力评测作为实验条件，允许人机协作过程作为机制，允许迁移作为核心结果，同时避免在首阶段承担完整职业能力体系、动态课程重构和跨专业推广的证明责任。

## 十、希望专家重点指导的问题

1. **核心构念选择**：项目最值得作为主要科研对象的是 Agent 职业任务能力、人的适当依赖与接管、能力迁移，还是三者之间的因果关系？首阶段是否应把迁移设为主要终点？
2. **学术定位**：若面向人工智能/NLP 研究，什么样的方法贡献才足以区别于普通 AI 教育应用和现有 Human-Agent Collaboration 研究？是否需要形成新的评价协议、任务结构表示或可复现 Benchmark？
3. **实验识别策略**：首阶段应优先采用冻结的受控 Agent 输出以获得内部效度，还是使用真实在线 Agent 以获得生态效度？两阶段结合的最低可行设计是什么？
4. **任务与效度**：Python/CSV 数据清洗或数据库一致性诊断是否足以承载“基础—协作—迁移”关系的初步检验？怎样证明任务具有职业意义，而不仅是课程作业？
5. **原创性边界**：相对于 ChemEval、OSWorld、REL-A.I.、CollabSkill 和生成式 AI 学习效果研究，SkillShift 最可能成立、也最值得持续投入的差异化问题是什么；哪些现有设想应尽早放弃？
