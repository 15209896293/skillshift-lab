# R0 产品重定位决策记录：AI 协同作业过程治理

## 状态与效力

- 状态：已确认的产品方向；仅记录已讨论并确认的决策，不代表任何功能已经实现或验证。
- 日期：2026-09-23。
- 适用范围：SkillShift Studio R0 及其后续需求、技术、质量规范。
- 优先级：当本文件与 V3.0 总纲或现有 R0 规范冲突时，以本文件为准，直到它们完成一致性修订。

## 1. 已否定的前提

以下表述不再作为 SkillShift Studio 的产品成立理由：

1. “学生为什么不用 Codex、Cursor 或其他主流 Agent，而要改用 SkillShift。”
2. “SkillShift 的 Agent 或通用 Workspace 会在能力上胜过主流 Agent。”
3. “平台可以可靠地阻止学生在平台外使用 AI。”
4. “粘贴、低编辑量或相似提交可自动证明学生作弊、使用外部 AI 或能力不足。”
5. “R0 的 Python Workspace 能代表 PyCharm、虚拟机及所有计算机教学形态。”

主流 Agent 可以是后续可替换的能力来源；SkillShift 不以与其竞争模型或 Agent 能力为目标。

## 2. 项目与 Studio 的层级关系

SkillShift Lab 的核心不是自研 Agent，也不是把 Studio 做成独立通用开发平台。核心研究问题是：**Agent 进入职业教育后，职业知识、基础能力、任务结构和人机协同能力如何变化，以及学生如何把基础能力迁移为可验证的人机协同职业能力。**

Studio 是服务该研究主线的产品化载体和研究基础设施：它提供真实任务、允许 AI 协同的受控场景、可验证结果、最小必要过程证据和教师干预入口。它必须对学生和教师有真实教学价值，但不以在 Agent 能力上超过 Codex、Cursor 或其他主流工具为项目目标。

产品运行数据不是研究结论，也不会自动成为研究数据。研究使用需要独立目的、授权、最小化、去标识化和版本治理。

## 3. 新的产品定位

> **SkillShift Studio 是一个允许 AI 协同、但让作业过程重新可见、可复核、可干预的教学工作平台。**

产品不阻止 AI，也不把 AI 使用本身视为违规。它把教师已允许的 AI 协同作业放进一个受控过程：学生可使用平台内提供的基础 LLM 与 Agent 能力完成作业；系统记录最小必要的过程证据；教师得到可解释的过程摘要和待复核项；教师而非算法作出教学判断。

## 4. 需求者、使用者与价值

| 角色 | 身份 | 获得的价值 |
| --- | --- | --- |
| 院校 / 教师 / 导师 | 拟验证的需求者、规则制定者、最终判断者 | 在允许 AI 的作业中恢复过程可见性，获得可处理的复核队列和教学反馈依据。R0 尚未证明学校或正式课堂会采纳。 |
| 学生 | 完成作业的使用者 | 获得已配置的作业环境、基础 AI 协作能力、可运行的项目工具，以及说明和补正自身过程的机会。 |
| SkillShift Lab | 长期研究主体 | 通过产品获得研究所需的真实任务、过程与结果条件；仅在另行同意、最小化和脱敏后使用研究数据。 |

平台的价值不是“比外部 Agent 强”，而是“在允许 AI 的教学任务中提供可信、可解释的过程治理”。

首阶段可由教师、导师、社团或训练营组织非计分练习；“院校正式采购、正式课堂强制提交”属于待验证扩展，不得在 R0 前当作既有需求或产品事实。

## 5. R0 业务闭环

```text
教师创建一项允许 AI 协同的作业
→ 配置任务、提交要求和必需过程证据
→ 学生在平台内完成 Python 项目练习，并可使用基础 LLM / Agent
→ 平台记录最小必要的 AI、编辑、运行、错误、文件变化和提交事件
→ 形成作业产物、过程摘要和带理由的待复核项
→ 教师查看、反馈、要求解释或补正
→ 学生补充解释、修改或重新提交
```

R0 的目标是验证该闭环是否可用，不是验证学习成效、职业能力、AI 替代率或对外部 AI 的完全防止。

## 6. 过程证据与异常边界

R0 可记录的平台内事实包括：任务配置、提示和 AI 输出的必要元数据、AI 建议的采纳/修改、文件变化、平台内粘贴事件、命令运行、报错、Artifact 和提交。

系统不能知道粘贴内容的外部来源，也不能观察学生在手机、其他浏览器、家中设备或未接入 IDE 中的 AI 使用。因此：

- “平台内大段粘贴”“过程很少”“提交相似”等只能产生**待复核信号**；
- 每个信号必须显示来源、规则和证据，不能只给黑箱分数；
- 信号不得自动扣分、定性作弊或生成学生能力结论；
- 教师必须能作最终判断；学生必须有解释、补证或重新提交的路径。

## 7. R0 范围与扩展边界

### 6.1 平台级 AI 协作模式

教师不应为每项作业填写复杂的 Agent 权限或证据规则。R0 固定提供以下模式；教师创建作业时只需选择一种，系统自动应用对应的 Agent 权限、事件模板、学生默认检查点和教师端摘要逻辑。

| 模式 | Agent 行为 | 默认过程证据 | 默认学生检查点 |
| --- | --- | --- | --- |
| 仅问答 | LLM 解释和讨论，不直接操作项目。 | 提问、回答、学生文件变化和运行记录。 | 学生自行运行或提交自己的修改。 |
| 协作需确认 | Agent 可读取项目、提出计划和修改；关键动作需学生确认。 | 计划、确认、修改、命令运行、错误和结果。 | 学生确认关键计划或修改。 |
| 自主协作 | Agent 在已绑定的受控 Workspace 内自主读写、运行和安装项目依赖。 | Agent 动作、文件差异、运行结果、停止/接管和提交。 | 学生查看最终运行结果，并完成一次验证说明、补正或重新提交。 |

“自主协作”是教师端产品名称，不使用“完全访问”表述；它始终受 Workspace 根目录、非管理员身份、资源限制和工具策略约束，不拥有宿主机、私人目录、凭据或其他 Workspace 的访问权。

模式不构成能力评分，也不自动证明学生理解。它们只为不同教学意图建立可解释、可比较的过程边界；教师可根据作业目标选择模式，但 R0 不开放自定义权限编排。

### R0：学生桌面 Studio / Agent Node + 教师 Web 端

R0 选择一项非计分、允许 AI 协同的 Python 项目练习。学生在**本机受控 Code Workspace** 中使用桌面 Studio / Agent Node 完成任务；教师和导师使用 Web 端创建任务、查看复核队列并发起反馈；平台服务端负责账号、任务、模型网关、证据同步和产物元数据。

```text
教师 / 导师 Web 端
  创建作业、选择协作模式、复核、反馈
                    ↓
平台服务端
  账号、任务、模型网关、证据同步、产物元数据、研究数据隔离
                    ↓
学生桌面 Studio / Agent Node
  本机 Workspace、基础 Agent、Python 运行、权限确认、停止/接管、过程事件采集
```

这一选择不是要把 Studio 做成全功能 IDE，也不是替代 PyCharm。桌面端只控制自身绑定的 Workspace 和平台内 Agent 行为；不得扫描全桌面、监控私人目录或宣称能阻止外部 AI。纯 Web 可承担教学管理和远程服务交互，但不能作为本机文件、终端、运行环境和持续 Agent 控制的唯一承载面。

桌面外壳的具体技术路线、离线策略、模型在本机还是服务端运行、以及受限进程隔离强度均尚未选定，必须在开始工程前以 ADR 和 Spike 验证，不能由本决策记录替代。

### 后续：Evidence Adapter，而非代码检测扩张

```text
Assignment + AI Policy + Evidence Contract
        ↓
Code Workspace Evidence Adapter       ← R0
PyCharm Evidence Adapter              ← 后续，部分可观察
VM / Linux Lab Evidence Adapter       ← 后续，部分可观察
Database Lab Evidence Adapter         ← 后续
```

PyCharm 插件或外部 IDE 接入即使未来实现，也只能采集启用接入后的部分编辑、运行和文件证据；不得宣称它能证明不存在外部 AI。虚拟机及其他计算机教学场景同理。

## 8. 数据、隐私与安全边界

- R0 先使用合成任务和非计分练习；真实学生试用前需明确告知、最小数据规则和相应授权。
- 不采集全桌面、私人目录、无关浏览记录、手机活动或真实凭据。
- 平台内 Agent 的行动范围受 Workspace 边界、资源限制和工具策略约束；“自主”不等于宿主机完全访问。
- 产品运营数据与研究数据必须分离；研究结论、能力评分和对外发布需要独立研究治理。

## 9. 分阶段验证

R0 的首要产品验证是：教师/导师能否低负担完成创建—复核—补正（A），以及学生能否在允许 Agent 时完成任务关联的验证、解释、纠错、接管或补正（B）。职业任务结构的变化属于后续研究问题；R0 只为其提供受控任务条件。

| 阶段 | 输入 | 要验证的事实 | 不得声称 |
| --- | --- | --- | --- |
| A. 合成闭环 | 合成作业、模拟学生过程 | 事件、提交包、待复核规则和教师看板的技术闭环。 | 真实学生价值或学习效果。 |
| B. 教师流程验证 | 模拟案例、少量教师 | 过程摘要和待复核理由是否可理解、可行动且不明显增加负担。 | 学习效果或课堂规模可行性。 |
| C. 非计分自愿练习 | 明确告知的小范围真实使用 | 学生是否能使用内部 AI 完成任务，教师是否愿意据过程进行反馈。 | 外部 AI 已被阻止、研究结论或学生能力结论。 |

## 10. R0 成功与失败信号

R0 应观察：过程证据完整度、Artifact 是否可复核、待复核理由是否被教师认为有用、教师完成一次处理所需时间、学生是否能完成并补正任务、系统故障与错误率。

R0 不以 DAU、自动异常率、外部 AI “检出率”、学生能力分数或“AI 替代率”作为成功指标。

若教师认为摘要无用或工作量更大、学生无法在平台中完成基础任务、信号误报过多且无法解释，或过程数据无法支持公平复核，则应调整或停止该产品路径，而不是堆叠监控能力。

## 11. 尚未决策的事项

1. 三种模式在教师端的默认呈现与是否允许后续扩充；
2. 过程摘要与待复核规则的初始规则集和人工复核流程；
3. 学生验证说明、补证、重新提交和申诉的具体机制；
4. R0 内置 LLM / Agent 的供应商、成本和可用性；
5. 真实学生非计分练习的告知、授权、保留期限与校内流程；
6. PyCharm、虚拟机和数据库场景的后续 Evidence Adapter 契约。

这些事项未决定前，不得假定它们已经具备或把 R0 扩展为正式课堂评分系统。

## 12. 2026-09-24 首条交付路径更新

项目负责人已确认：R0 的首条可实现闭环先验证通用教育 Agent 对教师创建、学生协作、提交、复核与补正的支持；它不以 Agent 在学生电脑上自动执行任意代码为前置。

因此，本记录第 7 节中的本机 Code Workspace 由首条闭环的必要组成调整为后续可选 Evidence Adapter。首条闭环只处理平台内任务、Agent 引导、学生主动提交和教师反馈，不调用本机文件、Shell、进程、依赖安装或网络工具。既有 Foundation Spike 的 PARTIAL 结论仍然有效，但不阻塞这条无本机自动执行路径。

**网络边界澄清：** 本项目不禁止学生正常使用互联网、浏览器或课程所需网站。“Agent 不调用网络工具/不联网搜索”描述的是平台内 Agent 的工具权限，不是限制学生上网。Foundation FS-04 与 Windows AppContainer 网络负测仅针对未来可选的本机代码/进程执行 Provider，不构成课堂网络政策，也不阻止本机网页/API或学生自行查阅网络资料。任何平台服务端模型请求则受 Gate B/生产就绪门禁约束，当前仍未进行真实调用。

详细且可实施的边界以 `R0_AGENT_FIRST_DELIVERY_DECISION.md` 和 ADR-004 为准；真实模型、真实学生、部署和本机代码执行仍需各自的独立决定与证据。

## 13. 2026-09-25 项目型工作空间范围修订

项目负责人已选择项目型 Agent 首个产品切片（方案 B），详见 `R0_PROJECT_AGENT_WORKSPACE_DECISION.md`。第 12 节描述的无代码闭环继续作为已验证的确定性流程 Harness；它不再限定目标产品必须是纯文本交互。首个面向用户的切片应设计独立教师 Web 与学生项目工作空间，支持项目上下文和代码编辑/Agent 建议。

本修订**不开放代码执行**：本机、浏览器后端或远端执行位置均未选定，必须有独立安全规格与验证后才可运行学生/外来项目。它也不授权真实模型调用、身份、真实数据、部署或研究数据导出。Python + CSV 暂为合成 Golden Path；学生仍可正常访问个人浏览器和互联网。
