# R0 研究—任务—证据契约

## 状态与效力

- 状态：**Active**（2026-09-24）；已确认作为 R0 产品验证契约。正式研究问题、研究设计和研究授权仍须另行确认。
- 适用范围：R0 首条 Agent-first 教学闭环，以及后续可选的学生 Studio / Code Workspace Evidence Adapter。
- 不构成：学生评分规则、作弊判定规则、正式研究审批、学生研究同意或研究结论。
- 关系：本文件把 `R0_PRODUCT_REPOSITIONING_DECISION.md` 的“研究主线—Studio 载体”关系转成可执行的任务与证据边界；如冲突，以产品重定位决策为准。

## 1. 为什么需要这个契约

Studio 能产生过程事件，不代表这些事件本身就是研究证据，更不代表它们能证明学生理解、能力迁移或外部 AI 使用情况。

每一项 R0 任务必须把下列六件事写清楚：

```text
研究关注的问题
    ↓
真实教学任务与允许的 AI 协作方式
    ↓
学生仍须承担的验证、判断、解释或补正责任
    ↓
平台内可观察事实和结果 Artifact
    ↓
教师可作出的教学动作
    ↓
在取得独立授权后，才可进行的最小化研究解释
```

没有这条链，平台只能保存日志，不能声称它在支持 SkillShift 的研究问题。

## 2. R0 共同关注的问题与边界

R0 先验证教师低负担闭环与学生有效参与闭环（A+B），并只为后续研究提供受控、可复核的真实任务条件。它可为以下**待研究**问题建立条件：

1. 当任务允许不同程度的 Agent 协作时，学生在哪些环节仍需要验证、判断、纠错、接管或解释？
2. 原有职业技能任务中的“产出完成”与“可复核的人机协作过程”之间，有哪些不一致或新增要求？
3. 教师是否能基于有限、可解释的过程事实提供补证、解释或补正反馈，而不增加不可接受的工作量？

R0 不回答、也不得暗示回答：

- 学生是否一定掌握某项能力；
- 外部 AI 是否被阻止、检测到或完全未使用；
- 某种 Agent 模式必然提升或降低学习效果；
- 某名学生是否作弊、能力不足，或可用过程日志生成能力画像；
- “AI 替代率”。

## 3. 通用 R0 任务契约

Python 是首个 Evidence Adapter 验证环境，而不是项目任务边界。每个未来 Adapter 都应复用下列任务字段；其具体运行环境可以不同。

| 契约项 | R0 最小要求 | 目的 |
| --- | --- | --- |
| 任务目标 | 明确可交付的职业/学习产物与完成条件。 | 避免把“和 AI 聊过”当作完成。 |
| 任务环境 | 指定已绑定的 Workspace、运行命令、材料和可验证输入。 | 限定平台可观察范围。 |
| AI 协作模式 | 仅问答、协作需确认或自主协作之一。 | 形成可比较、可解释的权限边界。 |
| 人类责任 | 至少指定一次结果验证，以及一次解释、纠错、接管或补正责任。 | 防止 Agent 完成后学生只点击提交。 |
| 结果验证 | 任务级验证命令、Artifact 或人工检查项。 | 将结果与过程事实分开。 |
| 提交包 | Artifact、验证结果、必要的学生说明和平台内事件引用。 | 使教师能复核而非查看全量日志。 |
| 教师动作 | 接受、请求说明、请求补证、请求补正或标记环境问题。 | 保留教师判断与学生补正路径。 |
| 告知与数据范围 | 告知 AI 权限、记录范围、教师可见范围、补正路径和研究数据边界。 | 防止把过程治理误作全量监控。 |

“人类责任”应随任务目标变化，不能被固定成统一能力评分。例如，数据清洗任务可要求学生验证输出与解释异常值；程序调试任务可要求学生复现故障并说明最终修改为何有效。

## 4. 可观察事实、教学动作与禁止推断

| 平台内事实 | 可支持的教师动作 | 不可推断 |
| --- | --- | --- |
| 已记录 Agent 工具调用、文件差异和运行结果 | 查看过程摘要；要求学生解释或验证最终结果。 | 学生一定理解或没有理解。 |
| 任务验证器通过或失败 | 接受结果，或请求学生补正、重新运行。 | 学生独立完成，或学生没有努力。 |
| 平台内大段粘贴事件 | 请求说明、补证或复核。 | 粘贴来源、外部 AI 使用、作弊。 |
| 缺少规定的任务内事件 | 请求补充验证或说明。 | 学生一定绕过平台或使用外部 AI。 |
| Node/运行环境异常 | 标记环境问题并提供恢复路径。 | 学生个人能力不足。 |
| 自主协作模式下的 Agent 大量动作 | 请求学生完成验证说明、纠错或补正。 | 学生没有参与、成果不属于学生。 |

任何未来信号都必须先增加一行这样的“事实—允许动作—禁止推断”记录，才能进入教师复核队列。

## 5. 双层数据边界

### 5.1 运营与教学层：默认可用

为完成作业工作流，可保存任务配置、平台内 Agent 与运行事件、任务验证结果、Artifact 元数据、教师反馈和补正状态。范围只限绑定 Workspace 和任务需要的事实。

该层数据用于支持提交、复核、反馈、故障恢复和必要审计；不自动成为研究数据，也不能生成能力结论或自动成绩。

### 5.2 研究层：必须另行授权

将运营数据用于研究前，必须逐项完成：独立研究目的与问题、适用审批/授权、最小化字段、去标识化、导出版本、访问者、保留期限和删除/退出处理。

研究分析必须保留任务版本、验证器版本、Agent/模型版本、Node 版本和样本选择条件；否则不同环境下的过程不可比较。研究报告必须区分事实、解释、局限和不能推断的内容。

## 6. R0 的首个 Agent-first 验证模板

R0 的第一个任务用于验证这条契约，不代表项目只做文本任务或不再支持 Python：

1. 提供冻结的合成教学任务、明确目标、可交付响应和至少一种学生责任。
2. 教师选择平台级 AI 协作模式；不配置自定义监控或评分公式。
3. 学生在平台内使用确定性教学引导适配器，不触发本机文件、代码、Shell 或网络工具。
4. 学生提交一次与任务有关的验证、解释、纠错或补正，不能只提交 Agent 文本。
5. 平台形成最小提交、事件引用和可能的待复核理由。
6. 教师只基于任务内事实采取一次可解释动作；学生可完成补证、解释或重新提交。

首个任务的通过只代表“任务—协作—复核—补正”链可运行；不代表学习效果、市场需求、课堂规模、真实模型效能或研究假设成立。本机 Python Code Workspace 是后续独立验证的 Evidence Adapter。

## 7. 工程与试点验收边界

在工程 Spike 或真实学生试用前，分别检查：

| 阶段 | 最小验收 | 不得跨越 |
| --- | --- | --- |
| 合成闭环 | 六项任务契约均有结构化记录；结果、事件、教师动作和补正可回放。 | 不使用真实学生或真实隐私数据。 |
| 教师流程验证 | 教师能理解每个待复核理由，并能完成一次动作；记录处理时间与困惑点。 | 不宣称教师需求或教学效果已获验证。 |
| 自愿非计分试用 | 学生获得明确告知；能安装/使用 Node、完成基础任务并获得补正路径。 | 不作为强制课堂、成绩处理或研究数据收集的依据。 |
| 研究使用 | 已完成独立授权、最小化、去标识化、版本冻结和导出记录。 | 不从未经授权的运营数据产生研究结论。 |

## 8. 仍待确认的决定

1. 首个正式研究问题、目标人群、比较条件和可接受的证据强度。
2. 哪些职业任务类型最能代表“基础能力—Agent 协作—验证/接管”的变化，而不把项目缩减为 Python 练习。
3. 学生说明、纠错或接管的最小形式；它应真实有用但不能成为教师额外批改负担。
4. 研究授权、数据保留、退出与删除的制度路径。
5. 教师工作量的可接受阈值，以及任务何时应停止或退回重设计。
6. Node 本机事件在何种程度上可被视作可复核事实，及其离线、篡改和版本不一致的处理方式。
