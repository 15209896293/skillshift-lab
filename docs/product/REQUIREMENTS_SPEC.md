# SkillShift Studio R0 需求规范

## 状态与效力

- 状态：**Active**（2026-09-24；2026-09-25 范围修订）；保留确定性 Agent-first 流程 Harness 验收，并由 `R0_PROJECT_AGENT_WORKSPACE_DECISION.md` 与 `specs/R0-PROJECT-AGENT-WORKSPACE/README.md` 扩展目标产品为项目型工作空间。不同范围分别报告，不代表功能、真实模型或真实学生试用已实现。
- 上游：`R0_AGENT_FIRST_DELIVERY_DECISION.md`、`R0_PRODUCT_REPOSITIONING_DECISION.md`、`R0_RESEARCH_TASK_EVIDENCE_CONTRACT.md`、教师工作流与 ADR-004。
- 非目标：全功能 LMS、正式成绩、外部 AI 检测、全桌面监控、能力画像、研究实验、通用电脑自动化或与主流 Agent 比拼能力。

## 1. 产品目标

SkillShift 是研究主线下的教学工作平台；首条产品闭环是通用教育 Agent 对教学任务的支持，而不是让 Agent 自动运行学生电脑中的任意项目。

R0 先验证两项产品事实：

1. **教师低负担闭环（A）**：教师能创建一次任务、查看有理由的最小提交，并完成一次反馈或补正处理。
2. **学生有效参与闭环（B）**：学生在允许 Agent 协作时，能完成任务关联的验证、解释、纠错或补正，而不只是转发 Agent 输出。

首条闭环只使用冻结合成任务和模拟身份。它不证明学习效果、职业能力、外部 AI 使用情况、学校采购或课堂规模可行性。

## 2. R0 首条产品形态

```text
教师任务与复核界面
        ↓
平台任务、状态与提交服务
        ↓
学生学习界面 + 教育 Agent 适配器
```

原 Gate A 合成 Harness 处理任务文本、确定性引导、学生提交、教师反馈与补正，不调用 Shell、宿主文件系统、浏览器控制或代码执行。2026-09-25 已确认的目标产品切片另包含独立学生项目工作空间及代码编辑/Agent 建议体验；其实际 Agent、文件持久化和代码执行须各自通过后续 Gate，不得从 Harness 的通过外推。

Gate A 使用确定性 `ScriptedGuidanceAdapter` 验证产品编排，不能把模拟回答称作真实模型能力。项目负责人已否决 OpenAI API 路线；ADR-006 已确认 Gate B 的国产多模型网关产品边界：学校统一模型档位、教师可选 BYOK 的未来服务端凭据引用、学生无 Key 与可见基础降级。具体供应商、模型、费用、数据保留和部署尚未决定。无论选择何种模型，模型 ID、费用和运行时密钥都不属于学生客户端。

## 3. R0 必须具备

1. 教师以固定合成模板创建非计分任务，说明目标、允许的 Agent 协作、学生责任和提交要求。
2. 学生可查看任务并在平台内获得与任务关联的 Agent 引导。
3. 学生至少提交一次任务关联的验证、解释、纠错或补正；仅有 Agent 对话不能提交。
4. 系统生成最小提交：任务/模板版本、Agent 适配器版本、学生响应、状态、教师动作和事件引用。
5. 教师可认可、请求说明、请求补正或标记环境问题，并显示具体理由。
6. 学生可看到与自己有关的请求并提交说明、补正或重新提交。
7. 状态、事件和提交包可回放；错误、冲突或未完成状态不能伪装成学生过程不足。
8. 不自动输出成绩、能力结论、作弊结论、外部 AI 结论或研究结论。

## 4. 协作模式

| 模式 | Agent 行为 | 学生责任 |
| --- | --- | --- |
| 仅问答 | 解释任务概念与要求。 | 形成自己的任务响应。 |
| 引导需确认 | 给出步骤、例子或检查点；学生确认采用何种建议。 | 完成一次验证或说明。 |
| 任务内协作 | 在平台内组织计划、追问和修订建议；不获得本机工具权限。 | 完成验证、纠错、接管或补正之一。 |

模式只表示教学协作边界，不表示学生能力、独立完成或外部 AI 使用情况。

## 5. 作业与反馈状态

```text
DRAFT → ASSIGNED → IN_PROGRESS → SUBMITTED
SUBMITTED → REVIEW_REQUIRED | CLOSED | FEEDBACK_REQUIRED
FEEDBACK_REQUIRED → RESUBMITTED → REVIEW_REQUIRED | CLOSED
```

`REVIEW_REQUIRED` 仅表示教师需要处理；`CLOSED` 仅表示本轮教学处理结束。环境问题、适配器失败和同步问题必须作为独立状态或理由显示。

## 6. 最小数据与可观察边界

R0 可保存：任务配置、平台内 Agent 对话引用或摘要、学生主动提交、任务内验证/说明、教师反馈、状态变化和必要版本信息。

R0 不采集：全桌面、私人目录、键盘记录、浏览历史、手机活动、真实凭据或其他应用数据。平台内粘贴、过程缺失或提交相似只能触发人工查看，不得推断作弊、能力或外部 AI 来源。

运营数据不自动成为研究数据。研究使用需独立目的、授权、最小化、去标识化、版本冻结与保留/退出规则。

## 7. 可选后续能力

代码项目工作空间和代码编辑属于已确认的目标产品体验，详见 `specs/R0-PROJECT-AGENT-WORKSPACE/README.md`。宿主机文件访问、命令运行、依赖安装和学生项目执行仍不属于已获安全许可的能力；任何执行 Provider 必须建立独立规格，并在实施前满足 ADR-002 与对应 Foundation Spike 的适用安全证据，不得把当前 PARTIAL 证据描述为可用沙箱。

模型供应商、数据流、成本、真实学生告知、身份接入和部署也不属于本规格；它们需要独立决定。

## 8. 验收标准

| ID | 条件 | 最小证据 |
| --- | --- | --- |
| AC-R0-01 | 教师可用固定模板创建任务，不配置评分或监控公式。 | schema/unit test。 |
| AC-R0-02 | 学生可接收任务并使用确定性任务内 Agent 引导。 | adapter/integration test。 |
| AC-R0-03 | Agent 适配器不能调用网络、本机文件、Shell 或浏览器工具。 | negative test。 |
| AC-R0-04 | 学生提交包含任务关联的人类责任内容。 | validation test。 |
| AC-R0-05 | 提交包可定位版本、学生响应、状态和事件引用。 | manifest/schema test。 |
| AC-R0-06 | 教师可完成认可、说明、补正与环境问题处理；学生可回应。 | state-machine/integration test。 |
| AC-R0-07 | 四种冻结合成案例可完成完整闭环。 | bounded demo Artifact。 |
| AC-R0-08 | 界面与报告不产生作弊、能力、外部 AI 或研究结论。 | content/negative test。 |

没有真实运行证据时，功能只能称 Planned 或 Implemented，不能称 Verified 或 Done。
