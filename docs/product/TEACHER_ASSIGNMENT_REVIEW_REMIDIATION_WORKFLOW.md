# R0 教师作业创建复核与补正工作流

## 文档状态

- 状态：Active product workflow；不代表页面、接口或 AI 分析已实现。
- 范围：所有未来 Evidence Adapter 共用的教师流程；R0 仅用 Python Code Workspace 验证。
- 范围补充（2026-09-25）：教师复核流程同样适用于已确认的项目型 Agent 工作空间；代码编辑属于目标体验，代码执行仍由独立安全 Gate 控制。当前确定性流程仍只是合成 Harness。
- 上游：`R0_PRODUCT_REPOSITIONING_DECISION.md`。
- 不替代：教师最终评价、学校现有成绩制度、正式研究审批或学生申诉制度。

## 1. 目的

教师/导师端的价值不是显示全部日志，也不是自动判断学生是否使用外部 AI。它要用最少操作完成三件事：发布允许 AI 协同的任务、优先查看过程证据不足的提交、给学生可执行的反馈或补正机会。

R0 首先验证非计分、可自愿参与的任务组织场景；正式课堂强制提交、学校采购和成绩处理不属于已证实前提。

教师不需要为每项作业设计 Agent 权限或证据规则；创建时选择一个平台级 AI 协作模式即可。模式的权限、记录项和默认学生检查点由系统固定管理。

## 2. 作业创建

教师最小输入：

1. 作业标题与说明；
2. 任务材料或选择的任务模板；
3. 截止时间；
4. AI 协作模式：仅问答、协作需确认或自主协作；
5. 预期提交物和可用的结果验证方式。

R0 不开放教师自定义监控项、任意行为评分公式或复杂权限编排。首条 Agent-first 闭环由系统提供固定合成任务、任务级学生责任与结果检查；Python Code Workspace 是后续独立验证的 Adapter。

发布时系统向学生透明展示：允许的 AI 模式、平台记录的任务内事实、提交要求、教师可见范围以及补正路径。平台不得宣称这些记录覆盖学生的一切 AI 使用。

## 3. 学生提交状态

```text
DRAFT
→ IN_PROGRESS
→ SUBMITTED
→ REVIEW_REQUIRED（存在待复核信号）
→ FEEDBACK_REQUIRED（教师要求解释、补证或补正）
→ RESUBMITTED
→ CLOSED
```

`REVIEW_REQUIRED` 只表示需要教师查看，不是违规、作弊或低能力结论。`CLOSED` 只表示教师完成此轮教学处理；R0 不在该状态上自动生成成绩或能力画像。

## 4. 教师复核队列

教师先看到的是少量可解释的待复核项，每条必须包含：

- 信号类别；
- 对应的平台内事件或结果；
- 触发理由；
- 已知不可观察边界；
- 学生当前提交状态；
- 可用的教师操作。

R0 可先支持的信号类别：

| 类别 | 平台内事实 | 不得推断 |
| --- | --- | --- |
| 过程证据不足 | 缺少要求的运行、修改或检查点事件。 | 学生一定使用了外部 AI。 |
| 平台内粘贴事件 | 编辑器记录到大段内容粘贴。 | 粘贴内容的来源、学生是否作弊。 |
| 结果验证失败 | 任务验证器或规定运行命令失败。 | 学生没有努力或没有理解。 |
| 运行/环境异常 | 命令超时、依赖失败、Workspace 失败。 | 学生个人能力问题。 |
| 高自主协作 | 自主协作模式中的 Agent 动作和文件差异。 | 学生没有参与或一定缺乏理解。 |

相似性检测、外部 AI 检测、隐蔽风险评分和自动异常总分不属于 R0。

## 5. 教师操作与学生补正

教师对每项提交只需选择一项动作：

| 教师动作 | 系统结果 | 学生可做的事 |
| --- | --- | --- |
| 认可并关闭 | 保留当前过程与结果摘要。 | 查看结果。 |
| 请求说明 | 指定需要解释的运行、修改或 AI 协作片段。 | 提交简短说明。 |
| 请求补证 | 指定缺失的运行、验证或任务内检查点。 | 在 Workspace 内补充并再次提交。 |
| 请求补正 | 指定结果或过程需要修正的部分。 | 修改、运行验证并再次提交。 |
| 标记环境问题 | 从学生复核队列中区分平台/环境故障。 | 在修复后继续或重新开始。 |

教师可以添加简短文字反馈，但 R0 不要求逐段批改日志。学生看到的是教师请求和与自己相关的平台内事实，不显示黑箱风险分或对其他学生的比较。

## 6. 教师端最小界面

```text
课程 / 任务列表
  └── 单项作业概览：未开始、进行中、已提交、待复核、待补正、已关闭
        └── 待复核队列：理由 + 证据 + 操作按钮
              └── 单个学生：提交物、验证结果、过程摘要、教师反馈、补正记录
```

R0 不需要完整 LMS、班级管理后台、成绩册或大规模统计报表。它只验证教师是否能完成一次发布、一次有依据的复核和一次补正闭环。

## 7. 合成验证案例

在任何真实学生使用前，至少用以下合成案例走通工作流：

1. 正常完成且结果验证通过；
2. 平台内 Agent 协作后学生完成验证；
3. 平台内大段粘贴但结果可运行；
4. 缺少规定过程证据；
5. 结果验证失败；
6. Workspace 或依赖环境失败；
7. 教师请求说明后学生补充说明；
8. 教师请求补正后学生重新运行并提交。

验收不是“系统识别作弊”，而是每种情形都能产生准确状态、可解释依据、教师动作和学生后续路径。

## 8. 数据与研究边界

教学运行中只保留完成该工作流所需的作业、提交、平台内事件、验证结果和教师反馈。研究导出必须另行执行授权、最小化、去标识化和版本记录；教师端复核结论不能被自动解释为学生能力 Ground Truth。
